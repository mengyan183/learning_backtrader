## 1. 先说一个必须记下的教训：改哪一份

三个目标文件的本地状态**各不相同**，若一律"就地改"会出错：

| 文件 | 本地状态 | 处置 |
|---|---|---|
| `fg_system/human30.py` | **本地不存在**（Mac 侧 L3.5 新文件） | 从 `origin/main` 取回后再改 |
| `scripts/evolve_weekly.py` | 存在但**落后主线**（缺 M2.5 季度重标定整节 121~139 行） | **先对齐主线**（否则会把 Mac 的 M2.5 覆盖掉）再改 |
| `fg_system/backtest/attribution.py` | 与主线**相同** | 直接改 |

⇒ **判据**：动手前必须 `git show origin/main:<path> | diff` 逐文件比对，**"本地存在"不等于"本地是最新的"**。

### S-3 `scripts/evolve_weekly.py` — `--push` 静默失效

  —— `feishu_send.py` 的 argparse **没有位置参数** ⇒ `SystemExit(2)`，而 `check=False` 吞掉 ⇒ **永不成功也不报错**

  → 调 `feishu_send.py --pkg <pkg>` → **检查返回码，非零即报错退出**

## 3. S-4 `attribution.py` —— **误报，已撤回**（本轮最重要的记录）

**Agent 的说法**：`pipeline.py:114` 把 `target_position` 整体 `shift(1)`，而 `trend_blocked` 未 shift
⇒ `without_trend` 的掩码错位一天。

**我照做后**：`tests/backtest/test_attribution.py` **4 个既有测试转红**（`assert 0.245 == 0.49`）。

**追查证据链**（决定谁对）：

```
cli.py:338        us = pipeline.run_equity_v2()          ← 生产调用方拿的是这个
pipeline.py:662   def run_equity_v2(...):
pipeline.py:667       us = run(raw_dir=raw_dir, write=False)   ← 直接复用 v1 run() 的结果
pipeline.py:673       us["trend_blocked"] = trend < 1.0        ← 只【追加】趋势列
pipeline.py:674       return us
pipeline.py:86        core = signal_mod.core_position(idx_val)  ← v1 run() 里算 core，【没有】乘趋势系数
pipeline.py:114       out["target_position"] = ...shift(1)      ← 这个 shift 发生在 run_equity_v2 之前
全仓 grep trend_factor_series → 只在 :253/:258 用来【造 trend 列】，没有任何地方乘进 target_position
```

⇒ `run_equity_v2` 的输出里，`trend_blocked` 与 `target_position` 是**同一行对齐**的
（Agent 把 `run()` 内部的 shift 误套到了 `run_equity_v2` 的输出上）。
⇒ `without_trend` 的**原实现与其 docstring 契约一致**，4 个既有测试锁的正是这个契约。
⇒ **撤回改动**（仅保留一处无副作用的清理：`.eq(True)` 等价替代 `fillna(False).astype(bool)`，
消除 pandas downcast 弃用告警），并删除基于该错误前提的新测试文件。

**副产品**：顺带发现一处**真实但不同**的问题（**本次未改，供裁决**）——
`trend_factor_series` 从未乘进 `target_position`，即 `run_equity_v2` 的输出里
**看不到趋势打折**；而 `attribution.without_trend` 的前提是"值已被打折"。
两者口径是否一致，需要 Mac 确认（可能影响归因结论，但不属本次三条范围）。
