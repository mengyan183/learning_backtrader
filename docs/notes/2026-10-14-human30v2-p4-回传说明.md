## 五、🔴 P4 实施中发现并修掉的 **4 处真实缺陷**

### 缺陷 1：`judge_via_llm` 的降级设计**不可执行** ✗
- 原设计：`_degrade()` 把 transcript 的**自由文本**回答喂给 `judge_all()` ✗。
- 但 `judge_all` → `judge_level` 要求 `{象限: [1|2|3] × 3}` ✗ ⇒ **自己抛 ValueError** ✗✗。
- **修法** ✓：`judge_via_llm(transcript, client=None, fixed_answers=None)` ——
  · 给了 `fixed_answers` ⇒ 走 `judge_all(fixed_answers)` ✓（**真降级** ✓）
  · 没给 ⇒ 四象限 `level=None` + `fallback="fixed_questionnaire"` ✓（**诚实"未判定"** ✓）
  🔴 **不得**把自由文本机械映射成 1/2/3 ✗（那是发明新规则 ✗）。

### 缺陷 2：`phase` 量纲错了 ✗
- 原实现校验 `phase ∈ {1,2,3}` ✗，但 `model.PHASES` 是**字符串** ✓
  （`'dissonance'/'uncertainty'/'discovery'` ✓，`assess.judge_phase()` 也返回字符串 ✓）
  ⇒ **合法相位会被误判为非法** ✗。
- **修法** ✓：校验改为 `set(model.PHASES) | {"unknown", None}` ✓，prompt 与 schema 同步改准 ✓。

### 缺陷 3：「输出无数字」与官方标题**互斥** ✗
- `model.LEVELS[1][0]` = `'1.0 顺从者 Conformist'` ✗ **自带数字** ✗
  ⇒ 直接渲染会**违反** §7.1 ✓。
- 且官方标题 `HUMAN 3.0 DEVELOPMENT ASSESSMENT RESULTS` 里的 `3.0` ✗
  与「一个数字都不许有」✗ **互斥** ✗。
- **修法** ✓：
  · 新增 `render.level_word()`：**剥掉** `^\s*\d+(\.\d+)?\s*` 前缀 ✓ ⇒ `'顺从者 Conformist'` ✓
  · **裁定**：§7.1 约束的是「**分数与 Level 数字**」✓，`Human 3.0` 是**系统名** ✓ ⇒
    数字校验**先剥掉固定标题**再断言 ✓

### 缺陷 4：我自创的「白名单消费者只读」守卫**语义自相矛盾** ✗
- 我把 `scripts/invest_research.py` 列为「只读展示消费者」✗ 并断言其不得含 `target_position`/`ZONE_EDGES` ✗。
- 实测：该脚本是**简报生成器** ✓，**本来**就合法读这些符号 ✗ ⇒ 断言**必然失败** ✗。
- **修法** ✓：**整条撤销** ✓（spec 的守卫 1 只要求「判决层不 import human30」✓，白名单是我加戏 ✗）。

> 缺陷 1/2/3 由实施 subagent 跑测试时**发现并拒绝猜** ✓（均报 BLOCKED + 给方案 ✓）；
> 缺陷 4 同样由 subagent 报出 ✓。全部深挖确认后裁定 ✓。
