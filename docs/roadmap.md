## 扩展规划（跳出当前架构，参考市面同类产品）

> 调研参考：TradingAgents / QuantAgents / ContestTrade（多智能体投研）、Qlib / QuantConnect / vn.py / 米筐（量化平台）、CNN Fear&Greed / CFGI / CoinGlass / Market Mood（情绪指数）、FinRL-X / OpenBB（开源金融 AI）、walk-forward 方法学（对抗概念漂移）。
> 原则：所有方向仍在"数据裁判 + 人工审批"纪律内；每个子项都走变体 + 门控采纳。

### E1 多信号合成投研层（多智能体流水线）
- 用 OpenClaw/Hermes/Harness 编排投研流水线：Hermes 情绪/新闻分析 → Harness 深度归因 → OpenClaw 裁判组织多空辩论与风险委员会（借鉴 TradingAgents 五级流程）
- 贪恐指数子信号扩展：动量/波动率 → 期权 Put-Call、加密资金费率（CoinGlass）、新闻/社媒情绪（Market Mood）、个股广度
- 风险：多智能体"虚假共识"（辩论强化偏见）→ 必须独立裁判 + 每个子信号单独走门控

### E2 walk-forward 滚动进化（对抗概念漂移）
- 显式化概念漂移监控：滚动 IC 下降检测 → 告警触发季度 walk-forward 重标定
- 重标定 = 变体 + 人工审批，**不是直接调参**；借鉴"模型学到的是特定时期模式"教训（2018 动量失效）
- 借鉴 ContestTrade 内部竞赛：假说绩效衰减自动降级，弱假说归档

### E3 回测=实盘同代码的执行闭环
- 目标仓位计算共用同一份代码（QuantConnect/FinRL-X 组合语义统一，杜绝逻辑漂移）
- 富途已接：自动推送目标仓位确认到飞书 → 人工审批 → 一键执行
- 护栏：熔断、最大仓位、大单人工审批；执行自动化必须在纪律红线内

### E4 AI 因子引擎
- 个股系统指数扩展成正式因子库：LLM 生成因子草稿 → 数据裁判跑 IC/IR/衰减检验 → 合格入库（借鉴 Qlib/米筐因子研究）
- 因子注册/检验/跟踪衰减流程文档化

### E5 主动投资 Copilot
- OpenClaw 升级为"问持仓/问归因/问风险"问答助手（飞书即入口，借鉴 OpenBB Copilot）
- 手机 PWA 看板从查表变问答

### 扩展规划落地顺序
| 阶段 | 方向 | 前置 |
|---|---|---|
| 近期（回测恢复后） | E2 漂移监控 + E3 执行确认流 | 基准回测 |
| 中期 | E1 多智能体投研 + 情绪子信号 | 数据管线稳定 |
| 远期 | E4 因子引擎 + E5 Copilot | E1/E2 沉淀 |

### 扩展纪律（新增）
- 不引入黑箱（RL/深度模型）作为裁判：只借鉴其"环境/组合语义统一"，可追溯优先
- 每个扩展子项独立走"假说 → 变体 → 审批"；未批准的扩展不落地
- 扩展设施同样受防过度工程约束

## 纪律红线（不可突破）

1. **LLM 永不判决**：回测 + pytest 是唯一裁判，LLM 只出假说与草稿
2. **OOS 禁止调参**：任何参数改动必须先跑变体，OOS 不劣化才进提案
3. **等价性守卫**：默认行为逐位不变是硬红线
4. **无新增前视偏差**（§10 红线）
5. **人工审批**：第 8 条流程最终签字后才动 config.py

## 风险与监控

- **数据断供**：05:30 `sync_positions.py`（FG_SYNC_MODE=live）依赖富途/OKX 可达，中断会静默断数据 → 每周看 `/tmp/fg_daily.log` + 飞书推送异常时人工检查
- **回测文件长期缺失**：第二层全部阻塞 → 优先推动补传
- **过度工程**：进化设施本身要克制，核心产出永远是"可验证的交易改进"，不是工具数量
