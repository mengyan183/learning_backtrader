## 12.42：**弹药池重新装填** —— 回撤修复 ≤5% 且距上次 ≥90 天（**规则级**）

**为什么**：`ammo_released` 只增不减，没有任何重置逻辑 ⇒ 弹药池**一生只有 20%**。
实测 `Data/state.json` = `[0, 1]` ⇒ 2/3 已释放（13.33%），剩的一批要 **-60% 回撤**
才触发 ⇒ 机制在第一次大熊市后名存实亡。

**改了什么**：
- `config.AMMO_RESET_LEVEL = 0.05`（回撤修复到此水平 ⇒ 视为「本轮危机结束」）
- `config.AMMO_RESET_MIN_DAYS = 90`（两次装填最短间隔，自然日）
- `signal.SignalState` 新增 `last_ammo_reset` 字段（随 `state.json` 持久化）
- `signal.update_ammo(state, drawdown, date=None)`：先判装填、再判释放；
  装填时**一并清空** `last_extreme_fear_date`（整轮危机结束，不该被 84 天前的
  极恐记录挡住）
- `pipeline.run()` 调用时传 `date_str`

**为什么不用「按年重置」**：长期阴跌（-20% 持续三年）会每年重放同一批 ⇒ 变成
「每年定投 6.67%」，与「分批抄底」的意图相悖，且在长熊里会过早打光。

**没改什么**：`DRAWDOWN_BATCHES`（-20/-40/-60）、`AMMO_CAP`（20%）、
`AMMO_PER_BATCH`、`CORE_CAP`、五档映射**全部不变**。

**验证**：`tests/test_signal.py` 新增 4 条（装填触发 / 90 天间隔 / 无日期不装填 /
清极恐冷却）；`tests/test_pipeline.py` 的单调性断言改为「只能整池归零，不许部分回吐」。

**未验证（必须补）**：**回测未重跑** —— 装填会让弹药变多，历史最大回撤可能恶化。
按第 8 条，本规则在回测（含样本外）通过前**视为未生效**，`position-plan` 类结论
仍按旧口径解读。

## 12.43：**新增「绝对水平」指数 `fg_index_abs`**（**口径级**）

**为什么**：`fg_index` 的六个因子**全部**走 756 日滚动百分位 ⇒ 它在结构上恒为
均匀分布 ⇒ 只能回答「相对过去三年排第几」，**回答不了「绝对风险有多大」**。
（VIX 若连续三年维持 40，分位会自动漂回 50 ⇒ 主指数认为「平静」。）

**改了什么**：
- `index.absolute_index(wide)`：固定阈值映射，**不做任何滚动归一化**
  - `vix`：10 → 100（极安静）/ 40 → 0（极恐慌）
  - `term`：VIX/VIX3M 0.8 → 100 / 1.3 → 0
  - `breadth`：MA200 上方比例（**本就是绝对量**）0~1 → 0~100
  - 三项等权，缺项按剩余归一
- `pipeline.run()` 输出新增一列 `fg_index_abs`
- 简报「市场快照」并列展示：`绝对水平 72（固定阈值口径）`

**没改什么**：`fg_index` 的合成、权重、五档映射、仓位决策**全部仍用相对口径**；
`fg_index_abs` 目前**只展示、不参与任何仓位计算**。

**阈值是判断取值，不是优化结果** —— 改阈值等于改口径，须同步本文档并重跑回测。

## 12.44：**压力测试接进简报**（**展示级**，不改规则）

**为什么**：`fg_system/risk_stress.py` 早就写好（`stress_report` /
`zero_out_answer`），但 `grep` 不到任何调用 ⇒ 用户只能看到「已经浮亏多少」，
看不到「再跌会怎样」。

**改了什么**：`invest_research._stress_section(snap)`，在「🛡️ 风控仓位」之后新增
「🩺 压力测试」一节：
- 指数再跌 20% / 35% ⇒ 按 `SHOUTU_API_PARAMS` 的 lever 传导（2x/3x）估算组合损失
- 全部归零（极端尾部）
- 预算取 **-50%**（用户 2026-11-20 明确问的数）
- 无杠杆映射的标的显式列出（按 1x 计）

**没改什么**：不参与任何决策，纯展示；`risk_stress` 的数字来源不变。

**口径提示**：这是**线性**估算（仓位 × 杠杆 × 指数跌幅），不含路径依赖、波动率
拖累、强平连锁 —— 真实损失通常**更差**，不是更好。

## 12.45：**`state.json` 拆成两份**（**工程级**）

**为什么**：`pipeline.run()` 与 `pipeline.run_portfolio()` **都写
`config.STATE_PATH`**，而每日链里后者后跑 ⇒ 用嵌套形态
（`{"portfolio":…,"us_equity":…}`）覆盖扁平形态（`{"ammo_released":[…]}`）⇒
任何读 `state.json` 的代码都得猜是哪种格式（2026-11-20 修简报文案时就踩到：
只读扁平键会误报「弹药池满」）。

**改了什么**：
- 新增 `config.PORTFOLIO_STATE_PATH = Data/portfolio_state.json`
- `run_portfolio(write=True)` 改写该文件；`STATE_PATH` 只由 `run()` 写

**没改什么**：两份文件的**字段语义**不变；`_load_state()` 仍读 `STATE_PATH`。

## 12.46：**连亏保护改「期初净值」为分母 + 标注减仓滑点**（**口径级**）

**为什么**：`day_pnl` 的定义是 `net_value` 的日差分（`sync_positions.fill_day_pnl`），
而分母原来用**当日收盘净值** ⇒ 亏得越多分母越小，**比率被系统性放大**。

实测（2026-11-19）：

| 口径 | 计算 | 结果 |
|---|---|---|
| 旧（期末） | -1072.79 / 5876.40 | **-18.3%** |
| 新（期初） | -1072.79 / 6949.19 | **-15.4%** |

而且那天拆开看是两段性质完全不同的事：

- `6949.19 → 6202.5`（-746.7）= 当日市场下跌
- `6202.5 → 5876.40`（-326.1）= **清仓的执行滑点**（一次性）

把一次性成本算进「当日亏损率」，会让清仓当天的数字天然难看 ✗。

**改了什么**：
- 分母改 **期初净值** = `当日净值 - day_pnl`
- `securities_mv` 较前一日下降 ≥15% 净值 ⇒ 判定「当日有大额减仓」
  ⇒ 文案追加「含当日减仓滑点」✓
- 触发条件从 `day_pnl ≤ -2% × 期末` 改为 `≤ -2% × 期初`

**没改什么**：2% 阈值、只提示不开新仓、**不加强制动作** 全部不变。

**为什么不加强制动作**（用户 2026-11-20 明确裁定）：本系统**全部为人工操作**，
没有任何程序化交易通道 ⇒ 强制动作只能表现为「简报上的一句话」，
加了也是伪约束。真实的约束力来自人在看到提示后的选择。

**验证**：`tests/test_brief_hygiene.py` 新增期初分母 / 滑点标注 / 无卖出不标注三条。

## 12.47：**波动率族权重 40.5% → 30%**（**规则级**）

**为什么**（评审第②条）：`vix 0.270 + term 0.135 = 40.5%`，而 `term.py` 自己的
docstring 就写着「与 F1 同属波动率族，存在共线性」✗ ⇒ 名义六因子，实际是
**押注波动率的单因子策略** ✗。对信用、流动性、盈利预期几乎不敏感。

**改了什么**：

| 因子 | 旧 | 新 | 变化 |
|---|---|---|---|
| `vix` | 0.270 | **0.200** | −0.070 |
| `term` | 0.135 | **0.100** | −0.035 |
| `breadth` | 0.135 | **0.210** | +0.075 |
| `putcall` | 0.100 | **0.130** | +0.030 |
| `price` | 0.225 | 0.225 | 不变 |
| `fed` | 0.135 | 0.135 | 不变 |
| 合计 | 1.000 | **1.000** | |

波动率族 **40.5% → 30.0%**；腾出的 10.5pp 给 `breadth`（与波动率相关性最低的
真实广度度量）和 `putcall`（情绪面，与 vol 相关性也低）。`price` / `fed` 不动
—— 没有证据支持动它们。

**没改什么**：因子实现、滚动窗口（756 日）、五档映射、`CORE_CAP`、弹药机制。

**未验证（必须补）**：**回测未重跑**。权重变化会改变 `fg_index` 的历史轨迹
⇒ 五档切换时点变化 ⇒ 最大回撤与换手都会变。按第 8 条，本改动在回测（含样本外）
通过前**视为未生效**。

## 12.48：**ICIR 按重叠倍数折算**（**口径级**）

**为什么**（评审第⑤条）：`IC_WINDOW=60` 的滚动 IC + `HORIZON=20` 的前瞻收益
⇒ 相邻窗口重叠 40 天 ⇒ IC 序列高度自相关 ⇒ `ic.std()` 被**系统性低估**
⇒ ICIR 被放大。实测全窗 ICIR −1.16 / 近窗 −1.95，都是放大后的值。

**改了什么**（`fg_system/factors/eval.py`）：

```python
def icir(ic_series, overlap=1):
    raw = mean / std
    adj = raw / sqrt(overlap)      # 有效样本 n/overlap
    return {"icir": adj, "icir_raw": raw, "overlap": overlap, ...}
```

`evaluate()` 自动传 `overlap = ceil(window / horizon)` ⇒ 当前 = 3
⇒ 折算系数 **1/√3 ≈ 0.577**。

**没改什么**：IC 均值、正值比、`n` 都不变（均值本身没有系统性偏差）。

**副作用（已知并接受）**：`drift_monitor` 的阈值 `|ICIR| < 0.3 / 0.5` **没动**
⇒ 在新口径下相当于变严（约 1.7 倍）⇒ **会更容易报「预警/告警」**。
方向偏保守（宁可多报），但阈值本身应当重新标定 —— 登记为待办。

**没改什么**：防抖三条约束的数值、`instruction_card()` 的行为。

## 12.50：**存量仓过渡期结束**（**规则级**，用户 2026-11-20 裁定）

**为什么**：`LEGACY_TRANSITION_UNTIL = "2027-11-09"` 让 6 个存量标的**豁免**
1% 风险硬上限，只按贪恐系数减仓。用户裁定提前解除 —— 清仓四个之后，
剩下的 YINN / BTC 不再需要这条豁免。

**改了什么**：`LEGACY_TRANSITION_UNTIL` `2027-11-09` → **`2026-11-19`**

⇒ 简报的「减仓操作」会从「全部无减仓触发」变成**「超限，需减到上限」**，
且金额会很大。这是规则的正常输出，不是 bug。

**没改什么**：1% 公式（净值×1% / 2×ATR20）、`LEGACY_POSITIONS` 名单本身
（留着做历史标记，但已不生效）。

**未验证**：ATR20 若因数据缺失取不到，`risk_limit` 会为空 ⇒ 该标的跳过判定
（不猜），所以解除后**可能仍显示「未超限」** —— 那是数据问题，不是规则没生效。

## 12.51：**漂移阈值改「相对全窗基线」**（**口径级**）

**为什么**：第 12.48 条把 ICIR 按重叠折算（×0.577）后，`drift_monitor` 里
**绝对阈值** `|ICIR| < 0.3 / 0.5` 的含义就变了 ✗ —— 同样的信号衰减程度，
在新口径下更容易/更难触发，取决于折算系数 ✗
⇒ 绝对值阈值天生与「ICIR 怎么算」耦合，每改一次口径就得重标一次 ✗

**改了什么**（`scripts/drift_monitor.py`）：

```python
DECAY_ALERT = 0.30      # 近窗 |ICIR| < 全窗基线的 30% ⇒ 告警
DECAY_WARN  = 0.45      # < 45% ⇒ 预警
MIN_BASE_ICIR = 0.15    # 基线太弱 ⇒ 比值无意义，判「数据不足」
```

判定改为**近窗 / 全窗的比值**，与 ICIR 的量纲无关 ✓

**取整依据**：旧绝对值 `0.3 / 0.5` 是相对「全窗 |ICIR| ≈ 1.16（未折算）」定的
⇒ 折算成比值是 **0.26 / 0.43** ⇒ 取整 **0.30 / 0.45**（比旧口径略严，方向偏保守）。

**没改什么**：方向翻转仍是最高优先级告警；「|IC| 低于基线一档」仍触发预警；
`IC_WINDOW` / `RECENT` / `HORIZON` 全部不变。

**已知取舍**：比值判据在**基线本身很弱**时没有意义（0.02 的基线跌到 0.01
也是「衰减 50%」，但两者都是噪音）⇒ 加 `MIN_BASE_ICIR = 0.15` 兜底，
低于它直接判「数据不足」，不硬判 ✓

**验证**：`tests/test_drift_crosscheck.py` 新增 4 条（比值判据 / 跨量纲同结论 /
基线过弱 / 方向翻转优先）。

## 12.52：**第 12.47 条回退** —— 同窗口 A/B 未通过（**规则级**）

**为什么回退**：第 12.47 条把波动率族从 40.5% 降到 30%，当时**回测未跑**。
补跑同窗口 A/B（`scripts/weight_compare.py --backtest`）后结果如下：

| 指标（OOS，同一份 prices、同一 OOS 起点 2024-10-04） | 旧（40.5%） | 新（30%） | 差 |
|---|---|---|---|
| 年化 | 17.22% | 11.81% | **−5.41pp** |
| 最大回撤 | −20.62% | −20.31% | +0.32pp |
| Sharpe | 0.71 | 0.50 | **−0.21** |
| Calmar | 0.84 | 0.58 | −0.26 |
| IS 年化 | 6.72% | 6.27% | −0.45pp |

**同窗口自检**：两段的 B0（等权买入持有，与权重无关）年化完全一致
（OOS 28.09% / IS 39.54%）⇒ 确认是同一数据窗口 ✓

**机制**（不是玄学）：降波动率权重 ⇒ 指数更难触及极端档
（极度恐惧 6.8%→6.2%、恐惧 26.2%→24.8%、中性 38.3%→41.8%）
⇒ 策略在底部「恐慌买入」的机会减少 ⇒ **IC 虽微升（−0.358→−0.362），
组合收益仍下降** ✗
—— IC 是全体样本的秩相关，看不出「只在 5 个断点上交易」的损失。

**顺带纠正一个错误归因**：旧基线报告里的「OOS 年化 37.66%」是 **2026-10-11
的短窗口**下的数；同窗口下旧权重只有 **17.22%** ✗
拿「37.66% vs 今天 11.81%」说「权重崩了 26pp」是错的（B0 从 75.45% 掉到
28.09% 已经证明那段差异主要是市场）✓

**改了什么**：`config.WEIGHTS` 回到
`vix .270 / term .135 / price .225 / breadth .135 / fed .135 / putcall .100`
（波动率族 40.5%）✓

**没改什么**：`CRYPTO_WEIGHTS`（50/50）不变；第 12.48（ICIR 折算）、
12.49（防抖进简报）、12.50（过渡期结束）、12.51（阈值相对化）**全部保留** ✓

**验证**：`python scripts/weight_compare.py --compare old,new --backtest`
