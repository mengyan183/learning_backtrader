## 1. 背景与既有约束（本工程事实）

| 事实 | 出处 |
|---|---|
| 双端分工：Windows 无公网、无 `Data/`；Mac 是家里服务机，有公网/真实 `Data` | `docs/dual-end-workflow.md`、`docs/mac-tasks.md` |
| 手机 ↔ Mac 已用 **Tailscale** 打通，目前主要用来访问 Mac 上部署的网站服务 | 用户口述 + `docs/remote-access.md` §2 |
| 任务下发已有通道：Windows → Mac 靠 `fg-sync`（git）入库 + 飞书推快照；Mac 直读 `docs/mac-tasks.md` | `docs/mac-tasks.md` 头部 |
| 触发方式已定案为 **B**：并入 `scripts/push_todo.py` 快照的【Mac 端待执行】段 | `docs/mac-tasks.md` |
| 现状痛点：**人不在电脑前时，无法实时介入/审批 Mac 上正在跑的任务** | 本文要解决的问题 |

> 关键：现有机制解决的是「**任务怎么传过去**」，不解决「**任务跑起来后怎么盯着、怎么中途拍板**」。

## 2. 两个候选方案

### 方案 A：Paseo + Claude Code + DeepSeek V4.1-Flash

- **Paseo**：开源（AGPL-3.0）自托管 Agent 编排 daemon。桌面 / 手机原生 App / Web / CLI 四端，手机端与桌面功能对等。支持并行多 Agent，每个 Agent 独立 git worktree。自带端到端加密 relay，可复用 Tailscale。
- **Claude Code**：Anthropic 官方 CLI 编程 Agent，跑在 Mac 本地，直接读写仓库、执行命令、跑测试、提交 git。
- **DeepSeek V4.1-Flash**：通过 Anthropic 兼容端点（`https://api.deepseek.com/anthropic`）接入，按 token 计费。

### 方案 B：豆包（电脑版 + 手机遥控）

- 字节跳动 AI 助手。**工作模式**能力：操作本地电脑（虚拟桌面）、浏览器自动化、Skills 技能调用、定时任务、内置 Office 套件、飞书联动、手机遥控电脑。
- **AI 编程**能力：生成代码片段、运行 Python、预览 HTML。
- 计费：基础功能免费；专业版 68 / 200 / 500 元每月（标准 / 加强 / 高级）。

## 4. 与本工程现有机制的耦合点（分析时必看）

> 🔴 **前置事实（2026-10-27 用户补充，**推翻本节原判断** ✗）**
>
> **Windows 侧无法 push 到远程 git**（公司安全策略 ✗）。真实拓扑是**单向**的：
>
> ```
> Windows --飞书分片--> Mac --gitee--> Windows
>         （唯一出向）          （唯一回读）
> ```
>
> 三条推论，后续分析必须按这个来：
> 1. **飞书打包/还原那一段不是冗余，不能退役** ✗ —— 它是唯一出向通道 ✓；
>    降复杂度的方向只能是「减少打包次数 + 提高单次成功率」（打包前强制 `git fetch && git pull` ✓）。
> 2. **Mac 是唯一能 push 的端** ⇒ Mac 侧 agent 若自动 `commit`/`push`，
>    坏代码会直通 gitee 再回流 Windows ✗ ⇒「**禁 auto-commit**」门禁优先级最高 ✓。
> 3. 下表 `fg-sync` 那行的「Agent 提交后自动进入同步链路 ✅」**只对 Mac → Windows 方向成立**，
>    Windows → Mac 方向**不存在** git 路径 ✗。

| 现有机制 | 方案 A 引入后 | 豆包引入后 |
|---|---|---|
| `docs/mac-tasks.md` 任务清单 | 可继续用；Agent 可直读该表执行 | 无法直读仓库文件，需人工转述 |
| `fg-sync`（git 同步） | **仅 Mac → gitee → Windows 方向自动 ✓**；Windows → Mac 仍只能走飞书分片 ✗（见上方前置事实） | 不参与 |
| `scripts/push_todo.py` 快照 | 不受影响 | 不受影响 |
| Tailscale 隧道 | **可直接复用**（Paseo 支持） | 不依赖 |
| `docs/remote-access.md` 的鉴权纪律 | 需新增评估：Paseo daemon 端口暴露面 | 需新增评估：豆包云端权限范围 |
| 交易纪律 `docs/trading-discipline.md` §8（文档先行） | Agent 可能绕过流程直接改代码 → **需要约束** | 不涉及代码，风险低 |

> ⚠️ 重点风险：方案 A 的 Agent 具备**直接改代码 + 直接提交**的能力，与 §8「文档先行、一次只改一件事」的纪律存在冲突。
>
> ✅ **2026-10-27 已落地两道门**（不再是「需要设计」）：
> 1. **禁 auto-commit**：本机 PreToolUse 钩子拦截无授权 `git commit`（要求 `# user-confirmed-commit` 标记）。
>    但注意 —— 这只管**本机**；Mac 侧 agent 必须在它自己的 harness 里配同样的门 ✗。
> 2. **纪律门禁**：`scripts/pre-commit-discipline.sh`（已并入 `.git/hooks/pre-commit`）——
>    暂存区命中 `fg_system/signal/`、`fg_system/models/`、`fg_system/config.py` 时，
>    必须同时有 `docs/` 变更，否则拒绝提交 ✓。四组用例实测通过（规则代码无文档 ⇒ 拒 ✓）。

## 5. 场景适配速查

| 需求 | 结论 |
|---|---|
| 手机远程改代码、跑回测、审 diff | 方案 A，无对手 |
| 手机远程做 PPT / 表格 / 文档 / 生图生视频 | 豆包，方案 A 做不到 |
| 手机远程「看着 Agent 跑并随时拍板」 | 方案 A |
| 手机远程「操作 Mac 桌面上的任意软件」 | 豆包 |
| 月使用 < 5 次且只写代码片段 | 豆包免费版够用，省 1–2 小时配置 |
| 两个都要 | 都装，用途不重叠，豆包用免费版 |

## 6. 初步倾向（供 AI 复核，非结论）

- 若目标是**让 Mac 自动执行 `mac-tasks.md` 里的开发/数据任务** → 方案 A 结构性更合适（唯一能进仓库干活的）。
- 若目标是**办公产出 + 跨 App 自动化** → 豆包。
- **互补而非互斥**：方案 A 主，豆包免费版辅，年成本 < ¥200。
