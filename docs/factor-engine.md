# 因子引擎流程（E4）

> 目标：把"个股系统指数扩展"从一次性开发变成**可持续注册、检验、跟踪、淘汰**的因子库。
> 纪律：LLM 只出因子草稿；IC/IR/衰减数据是唯一裁判；入库/出库都走变体 + 人工审批。
> 状态：🔄 检验设施已就绪（fg_system/factors/eval.py），因子库运转等待回测基准。

## 1. 因子生命周期

```
草稿(LLM/研究员) → 注册登记 → 数据检验(IC/IR/衰减) → 门控入库 → 跟踪衰减 → 淘汰归档
```

每个阶段都有明确产物与门槛，缺门槛不流转。

## 2. 检验设施（已就绪）

模块：`fg_system/factors/eval.py`（E4 地基，2026-10-02 交付）

| 函数 | 作用 |
|---|---|
| `forward_returns(close, horizons)` | 未来 N 日收益（严格滞后于信号，无前视） |
| `rolling_ic(signal, target, window)` | 滚动 IC（Spearman=rank 后 Pearson，兼容旧 pandas） |
| `icir(ic_series)` | IC 均值 / IC 标准差 / ICIR / 正值比 |
| `evaluate(signal, close, horizons)` | 多前瞻完整评估（5/10/20/40 日） |
| `window_stats(...)` | 全窗 vs 近窗对比（漂移检测用） |

应用：`scripts/drift_monitor.py`（系统指数 vs SPY 未来 20 日收益，实测逆向稳定 IC -0.36）。

## 3. 因子注册规范

登记表：`evolution/factors.md`（待建，与 hypotheses.md 同结构）。每条因子必备：

| 字段 | 要求 |
|---|---|
| 编号 | F-001 起，自动递增 |
| 名称/公式 | 可复算（含数据源、窗口、权重），禁止黑箱 |
| 信号方向 | 正向/逆向（决定 IC 符号语义，见 §4） |
| 检验方法 | 目标收益 + 前瞻 + 窗口 |
| 入库门槛 | ICIR 绝对值 ≥ 0.5 且近窗不衰减（§4） |
| 状态 | draft → verifying → adopted / rejected |

## 4. 检验口径（硬规则）

1. **无前视**：信号日期 t 只对 t+1..t+N 收益，`forward_returns` 已保证
2. **逆向语义**：贪恐类因子按逆向指标设计，IC 恒为负是特性——判定用 `|IC|` 与方向翻转检测，不做符号修正（drift_monitor 已固化此语义）
3. **多前瞻**：至少 5/10/20/40 四个 horizon，IC 单调性说明信号时效
4. **ICIR 门槛**：|ICIR| ≥ 0.5 且样本 n ≥ 60 交易日才具备入库资格
5. **衰减门槛**：近窗（120 交易日）|IC| 不低于全窗 |IC| - 1σ，且无方向翻转
6. **对照组**：入库前与现有指数做冗余度对比（|相关| > 0.8 视为冗余，不重复入库）

## 5. 跟踪与淘汰

- **每日**：`drift_monitor.py --push-alert`（已接入 05:30 链），异常才推飞书
- **季度**：walk-forward 重标定 = 变体 + 人工审批（**禁止直接调参**）
- **淘汰条件**（任一触发即归档，状态 → rejected）：
  - 近窗 |ICIR| < 0.3 持续 60 交易日
  - IC 方向翻转（全窗与近窗异号）
  - 数据源断供 > 30 日且无替代
