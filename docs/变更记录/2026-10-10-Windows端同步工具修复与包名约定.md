## 依据

**① 包名（2026-10-10 实测两坑）**

- 包名带 `-` / `.` 会被 Mac 端 `mac_bootstrap.sh` 的标记正则
  `###FG:([A-Za-z0-9_]+):(\d+)/(\d+)###` 匹配不到 ⇒ **整包丢弃**。
- 同一包名先后发两次 ⇒ Mac 端看到**两个不同总数** ⇒ 判成「混了旧导出」⇒
  **整包跳过**（连本该能进的那份也进不去）。
  实测：`sync:1/8`（roadmap + .gitignore）与 `sync:1/2`（测试文件）并存；
  改用 `sync_1009a` 后一次入库成功（主线 `3e12bf4`）。

**② 编码（2026-10-10 实测）**

- Mac 端 Prompt 指定的**开工触发词「同步待办」是中文** ⇒ 原 `ascii` 读取直接
  `UnicodeDecodeError`，连 `--dry-run` 都跑不了 ⇒ **不修就永远开不了工**。

## 口径

| 项 | 旧 | 新 |
|---|---|---|
| `--pkg` 默认值 | `sync` | `sync_<MMDD>`（同日多次发加序号字母，如 `sync_1010a`） |
| 包名字符集 | 未约束 | 只允许 `[A-Za-z0-9_]` |
| 分片读取编码 | `ascii` | `utf-8`（base64 纯 ASCII ⇒ 对分片完全等价，零兼容风险） |

## 追加（2026-10-10 下午）：`feishu_send.py` 输出块缓冲 → 行缓冲

### 现象

用 `cmd start` 脱离窗口发分片时，`scripts/send_pkg.bat` 写的
`%TEMP%\send_<包>.log` **四五分钟一直是空的** ✗，看起来像「窗口没起来 / 任务没发」。
实测：脱离窗口**其实在正常发送**，只是输出**没有 flush** ✓。

### 根因

Python 的 stdout **重定向到文件时是块缓冲**（约 8KB 才 flush），而 `.bat` 用的是
`> "%TEMP%\send_%1.log" 2>&1` ⇒ 进程结束前日志一直为空 ✗。
这也解释了为什么 `send_pkg.bat __nonexistent__` 那次「看起来正常」—— 它**立刻报错退出**，
退出时把缓冲区 flush 了 ✓。

### 修复（本机生效，提交不了）

`scripts/feishu_send.py` 顶部加：

```python
for _s in (sys.stdout, sys.stderr):
    if hasattr(_s, "reconfigure"):
        _s.reconfigure(encoding="utf-8", errors="replace", line_buffering=True)
```

顺带修了它的 **GBK 输出**（此前「已发」在日志里显示成 `□ѷ□`，见 `AGENTS.md` §6.2）。

### 验证（2026-10-10）

- 修复前：脱离窗口日志 15s 内**必为空** ⇒ `scripts/send_pkg_guarded.sh` 的
  「15s 日志非空」自检**必然误判**为脱离失败 ⇒ 降级前台分批（实测触发过一次）。
- 修复后：`bash scripts/send_pkg_guarded.sh sync_1010g` 输出 `[脱离] 已启动` ✓，
  **19 片全程脱离、零人工分批** ✓；说明消息 1 片同样脱离成功 ✓。

### 影响

- `scripts/send_pkg_guarded.sh`（已入库）的**脱离路径从此可用** ✓，降级分支保留作兜底 ✓。
