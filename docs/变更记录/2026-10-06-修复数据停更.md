# 变更核实记录 · 修复数据停更（2026-10-06）

## 变更

1. **`fg_system/data/fetch.py` `_opener` 按域名分流代理**：
   - 新增 `config.PROXY_HOSTS = ("okx.com",)` 白名单；只有命中白名单的域名走
     `config.PROXY`（默认公司代理 10.30.6.49:9090），nasdaq.com / cboe.com /
     alternative.me 一律**直连**。
2. **`scripts/check_freshness.py` 新鲜度护栏增强**：新增 features/prices 尾行
   与**今天**的对比（滞后 >3 自然日告警），保留原有 features vs prices 对比。
3. **launchd `com.xingguo.fg-daily`**：`sync_positions.py` 补 `FG_SYNC_MODE=live`
   前缀（在家动态同步持仓/账户；公司电脑模式仍由 FG_STATIC_ONLY=1 控制）。

## 依据

- 现象：2026-10-06 用户发现看板数据停在 2026-10-02（滞后 4 天、无告警）。
- 日志 `/tmp/fg_daily.log`（2026-10-06 05:30 每日链）：
  `RuntimeError: 请求失败 https://api.nasdaq.com/api/quote/TQQQ/historical ...
  timed out`；同日 `freshness_warning.txt` 为空。
- 实测：`curl`/python 直连 api.nasdaq.com（assetclass=etf）可通；走
  config.PROXY（公司代理）超时；OKX 直连不可达、需走代理。

## 口径

- 代理分流：`host` 含 `config.PROXY_HOSTS` 任一子串 → 走代理；否则直连。
- 新鲜度阈值：数据尾行距今天 >3 自然日（吸收周末/节假日）即告警；
  features 落后 prices >3 天同样告警。
- 补拉口径：update_prices(增量 fromdate=2026-10-03) + update_indices +
  pipeline.run(write=True)。

## 影响

- prices/features 推进到 **2026-10-05**（美东周一收盘）：fg 指数 57.86 中性
  （原 54.9 中性）；持仓/账户 10-03 快照（下一日链同步）。
- 修复后每日链在**家里**可正常拉取 nasdaq/cboe 数据（不再受公司代理拖累）；
  公司电脑上 okx 仍走代理、nasdaq 直连行为不变。
- 本次事故根因若早被护栏发现，可在 10-04/10-05 自动暴露而非用户手动发现。
