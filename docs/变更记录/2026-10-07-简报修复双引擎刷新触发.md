## 三、修复内容

### 2. 守猪待兔全量展示（`build_snapshot_lines`）

### 3. 归因/裁判输出校验与降级

- 新增模块级常量 `_PREAMBLE_HITS`（"we need answer"/"我们需要回答用户"/
  "你的全部输出只能是"/"请直接输出"/"以下是今日"/"直接输出最终分析正文"/
  "你是量化交易系统"/"你是投研裁判"）与 `_THINKING_HITS`（"need calculate"/
  "hmm if"/"let's sum"/"need infer"/"need interpret"/"maybe scores" 等）
- `_clean_attribution(text)`：命中特征或 <80 字 → `None` 降级
- `_validate_judge(text)`：必须匹配 `评级[:：](强烈减仓|减仓|持有|加仓|强烈加仓)`
  且含"理由""风险"，否则 `None`
- `stage_attribution` / `stage_judge`：**校验失败重试一次、仍失败返回 None/降级提示**
- 渲染降级文案：「归因生成失败，已降级跳过」/「裁判未生成，已降级；以风控/归因
  结论为准」

### 4. 减仓操作双引擎（回答"按系数还是按价格减仓"）

- **引擎A · 价格风控（P1 1% 风险规则）= 硬敞口**：市值 > 1%风险上限 ⇒ 必须减到
  上限（无论系数），保护单笔风险 ≤ 净值 1%
- **引擎B · 贪恐系数（系统个股系数 + 守猪待兔系数档位）= 方向信号**：决定买卖
  时机，不单独触发强制减仓
- 动作矩阵：

| 引擎A（价格） | 引擎B（系数） | 动作 |
|---|---|---|
| 超上限 | 贪婪（≥卖出线） | 减仓（双触发，优先级最高） |
| 超上限 | 非贪婪 | 减仓至上限（仅降敞口，不追方向） |
| 合规 | 恐慌（≤买入线） | 持有/可加（恐慌买入区且敞口合规） |
| 合规 | 其余 | 持有观望 |

- `build_snapshot` 新增 `sys_fg` 个股系数：`symbol_fg_index(sym, prices=px)`
  （mom60/mom20/vol20 三因子；底层数据不足如 CRCG 回退市场级并标注）
- 新增 `action_brief_text(snap)`，挂到 build_brief 富文本+markdown 双路径
  「📉 减仓操作（双引擎：价格风控 × 贪恐系数）」节

### 5. 网页刷新触发底层数据更新（`fg_system/dashboard/freshness.py`）

- 新增独立模块（server.py 只调用入口，守卫测试 `inspect.getsource(server)`
  不含抓取字样，保持通过）
- `check_and_refresh()`（GET / 时调用）：
  - 仅检查**写盘类**数据（`prices.csv` 最后日期）新鲜度，过期（>3 天宽限）才触发
  - 后台线程执行：`update_prices`（增量）+ `update_indices`（幂等）+
    `sync_positions`（**FG_SYNC_MODE=static**，公司电脑不调外部 API）+
    `fetch_shoutu_api.py --date 今天`（**仅当天快照缺失**；已有当天记录跳过——
    守住覆盖语义防污染 + 额度）
  - **节流 10 分钟 + 防重入锁**；失败只写 `/tmp/fg_dashboard_fresh.log`，不影响页面
- 纪律演进说明：原「绝不抓取守猪待兔」→「绝不**无条件**抓取」：每次刷新都抓仍被
  禁止（污染当天样本 + 耗额度）；仅当天缺失时补一次是用户新需求且无害。
  守卫测试 `test_server_never_fetches_from_api` 保持通过，新增
  `tests/dashboard/test_freshness.py`（4 例）覆盖：过期判定 / 行情新鲜不触发 /
  行情过期触发 / 节流不重复触发。
