# 变更记录：守猪待兔停更修复（2026-10-07）

## 现象
早间研报（2026-10-07）中守猪待兔仍显示 2026-09-29。

## 根因（已查证）
1. `Data/raw/shoutu_fng.csv` 数据停更于 **2026-09-29**（9-30 起美股照常交易，缺口 ≥5 个交易日）。
2. 抓取脚本 `scripts/fetch_shoutu_api.py`（partner API 通道，8 标的逐标的查询）**不在任何自动调度内**：
   - `crontab` 为空；
   - launchd 无守猪待兔独立任务（仅有 fg-daily/fg-dashboard/fg-kb-update/fg-realtime）；
   - 每日链 `com.xingguo.fg-daily.plist`（05:30）命令序列含 fetch_fedwatch / update_prices / pipeline / check_freshness / sync_positions / evolve_* / invest_research / drift_monitor / fetch_sentiment，**唯独没有 fetch_shoutu_api.py**。
3. 结论：不是"抓取失败重试"，而是**从未调度**——守猪待兔此前靠手动/临时运行，9-29 后无人再跑。

## 修复
1. **补录今日快照**：`fetch_shoutu_api.py --date 2026-10-07`（今日无记录，首次写入安全；`append_records` 为 (date,symbol) 幂等覆盖语义）。
2. **接入每日链**：`fg-daily.plist` 在 `update_prices/update_indices` 之后、`pipeline.run` 之前插入
   `.venv/bin/python scripts/fetch_shoutu_api.py` —— 守猪待兔先更新，pipeline 用最新值算指数/简报。
   已 `launchctl bootout + bootstrap` 重载生效（`launchctl list | grep fg-daily` 确认）。
3. **验证**：`invest_research.py --dry-run` 复跑，简报守猪待兔日期 2026-10-07（AXTX -4.0 / CONL -15.0 / CRCG -85.0 / GDXU -91.0 / SOXL 27.0 / TQQQ 48.0 / UPRO 39.0 / YINN -69.0），verify 仅 WARN 指数数据日 10-05（features 未到 10-06/10-07，属正常滞后）。

## 遗留说明（诚实披露）
- **历史缺口（9-30 ~ 10-06）无法回溯补录**：守猪待兔 API 为**实时查询**，无历史快照接口；对历史日期执行 `--date` 会把当日实时值误记到历史日期（污染数据），故不做。历史缺口的影响：9-30~10-06 期间简报守猪待兔段缺数据（显示上次可用值或缺失）；自 10-07 起每日链自动累积，不再依赖手动。
- 若需历史回溯，唯一可靠路径是 partner API 提供历史接口后补录，或放弃（研究用途 `shoutu_etf_universe.csv` 同理）。
