## 1. 动机

v1（2026-10-10 落地）借用了 Human 3.0 的名字，但**只实现了原文五个组成中的两个**，
且**违反原文的一条硬约束**：

| # | 原文 | v1 |
|---|---|---|
| 1 | 四象限**各自**层级 ＋ 整体分 `Σ(层级分)/12` | 只有整体分（算法与原文一致 ✓，**缺象限分解** ✗）|
| 2 | 每层内 **3 相位** | 无 |
| 3 | **Traits**（Knowledge/Experience/Skill）| 无 |
| 4 | **Channels + Glitches** | 无 |
| 5 | 输出 Metatype + Lifestyle Archetype + 核心问题 | 输出分数 + Level |
| 6 | 🔴 **"Never show numerical scores in output"**〔Prompt〕| **显示分数/Level** ✗ **违反** |
| 7 | 假性转变 / 回退 / 跨象限解锁阻塞 / Pre-Trans Fallacy | 无 |
| 8 | 血统 AQAL + 螺旋动力学 + 九阶段自我发展 + 心流 | 只写「Dan Koe」|

**说明**：本提案早期版本曾基于二手译文声称「原文是分子/分母结构」「原文禁止取平均」
「层级判据是安全感来源 T/A/C」「36 条确定性查表」——**四条均已核实为错误并撤回**
（原文无分子/分母说；原文明确使用 `Σ/12`；原文无 T/A/C；原文 Metatype 为 AI 动态生成）。
详见设计 §0.2。

## 2. 变更内容

按 `docs/human30-v2-design.md` 实施，分 6 期（P1~P6，见设计 §11）：

1. 新建 `fg_system/human30/` 包（`model` / `store` / `assess` / `metatype`），
   旧 `fg_system/human30.py` 变**薄兼容层**（re-export）⇒ 旧调用点不改，可分期上线
2. **四象限各自层级**（补 v1 缺失的象限分解）+ **保留**整体分 `Σ(层级分)/12`（原文算法）
3. **相位**（x.1/x.2/x.3），记法 `Vocation 2.1`
4. **Traits**（Knowledge/Experience/Skill）+ **假性转变** + **回退** + **Multi-Level Straddling**
5. **Channels / Glitches**（只做只读提示，不做具体推荐 —— 主动偏离原文，已明示）
6. **Archetype 词表 + Lifestyle 6 类 + 跨象限解锁/阻塞**（照原文，确定性可算）
7. 🔴 **输出不显示数字分数**（原文硬约束）；**输出不含交易动词**
8. 去掉线性进步叙事（原文："不是越高越好"）

### 2.1 🔴 判定机制：**P-B′（承认这是 LLM 应用）**
评审 S-4 证明「无 LLM 判层」与「声称忠于原文」**不能同时成立** ——
原文的层级判定本质是 **LLM 自适应追问**〔Prompt〕，去掉它就不是原框架。
⇒ **判层 + Metatype 都走 🟡 追问**（= 原文机制）；**离线/模型不可用时降级**为固定问卷 + 确定性规则。
⇒ **连带义务**：见 §3。

## 4. 风险

- **中高**：v2 是**换内核**，会改动 `aggregate()` / `advice()` 语义。
  缓解：旧 API 签名与返回结构**不破**，旧调用点无需改动，可分期上线。
- 🔴 **新增 LLM 判决点（最高）**：P-B′ 使判层也走 LLM ⇒ 相对上轮评审「human30 全程确定性无 LLM」
  的结论是**净新增**。必须按 §3 正式登记 + 修订规划条款，否则视为红线②违规。
- 🟠 **降级路径的忠实度损失**：固定问卷三选一会丢失原文的"追问"（防自欺核心机制）
  ⇒ 降级时必须在输出中明示"非原框架判定"（设计 §8.3）。
- 🟠 **跨机**：数据在 Mac 本地 ⇒ Windows 侧看板定位为"本机无数据"，非空壳（设计 §8.1）。
- **数据风险**：Mac 侧已有真实打卡数据 ⇒ 必须**懒迁移 + 不重写文件**，先在副本上验证往返一致。
- **范围风险**：原文含 Traits/Channels/Glitches 等 v1 完全没有的组成 ⇒ 靠 P1~P6 分期消化。
