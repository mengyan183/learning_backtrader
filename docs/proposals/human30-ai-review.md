# C-2 变更提案：H-REV-001 Human 3.0 AI 复盘解读

**状态**：待 C-3 人工审批（用户 Y/N）
**提出**：2026-10-10
**关联**：Human 3.0 组合骨架（commit 7d76dac / 624d975）；docs/human30.md

## 1. 动机

Human 3.0 已落地确定性规则（Level 判定 / 短板 / 窗口统计），
但"为什么最近状态波动"这类解读仍是规则盲区。用户自评数据已积累，
需要一层自然语言复盘来辅助自我观察——**不改变任何交易判决**。

## 2. 变更内容（获批后落地）

1. `scripts/human30_review.py`：读取 Data/human30.json 最近 N 天序列，
   用本地模型（Ollama，随现有配置，无新增成本）生成一段 ≤200 字复盘：
   - 输入：最近 7/30 天 Level、均分、短板、市场快照（fg_index/zone）时间线
   - 输出：状态趋势观察 + 1 条可执行建议（如"短板连续 3 天在 职/事业"）
2. 简报接入：`invest_research.py` 的「🌱 Human 3.0 状态」板块追加
   `AI 复盘（🟡 研究参考，非系统信号）：...` 一行
3. 页面接入：Human 3.0 tab 状态卡尾部折叠块「AI 复盘」（同文案）

## 3. 边界与守卫（硬约束）

- **LLM 不判案**：复盘仅解读自评数据，禁止输出买卖/仓位/账户建议；
  输出固定前缀 `AI 复盘（🟡 研究参考，非系统信号）`
- **数据只读**：只读 Data/human30.json + Data/features.csv 尾行快照，不写任何状态
- **失败降级**：模型不可用/超时 → 自动降级为确定性窗口统计（window_stats 已有），
  绝不让 LLM 失败阻塞简报生成
- **无调参**：prompt 固定为规则模板，不随会话漂移
- **审批门槛**：本提案获批前不实现；获批后实现 + 测试 + 全量回归 + 提交

## 4. 风险

- 低。不触碰交易判决链；输出仅附加在自评板块，且带 🟡 标注。
- 潜在隐私：自评含个人状态 → 数据只在本地（Ollama），不外传。

## 5. 验收

- `python scripts/human30_review.py --days 7` 输出 ≤200 字、带 🟡 前缀
- 简报板块出现该行且不阻塞生成
- 全量 pytest 通过
