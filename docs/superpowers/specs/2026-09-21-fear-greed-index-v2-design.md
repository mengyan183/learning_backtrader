## 1. 背景与目标

### 1.1 v1 的交付状态（本设计的直接输入）

v1 功能全部实现、工程正确、前视红线未破，但**核心成功标准未达成**：

| 验收项 | 目标 | 实际 | 判定 |
|---|---|---|---|
| **最大回撤** | ≤ 35% | **-61.53%（TQQQ）/ -73.33%（SOXL）/ -60.56%（UPRO）** | ❌ **未达标** |
| 总收益 | 允许跑输买入持有 | 年化 27.55% vs 38.81% | ✅ 符合预期 |
| 换手次数 | 显著低于人工频率 | 370 次 / 10 年 ≈ **37 次/年** | ⚠️ 偏高 |
| 前视偏差 | 零渗入 | 平移 + 截断 + 独立 5 点验证 | ✅ |
| 拆股校验 | 可检出未复权 | 相对偏离 + 绝对兜底双检测 | ✅ |
| 因子相关性 | \|corr\| < 0.8 | 最大 0.595（vix↔price） | ✅ |

**根因**（验收报告 §2.2）：2022 年 TQQQ 全年 -79.2%，而策略**持仓均值 73.1%** → 策略 -59.1%。「恐惧时满仓」在**持续熊市**中演变为**接飞刀**：指数越跌、仓位越高、亏损越大。样本内 Calmar 仅 **0.06**，样本外 1.36 —— **v1 本质是个牛市策略**。

验收报告 §5 给出四个改进选项，**推荐 B（增加趋势过滤）**，理由：直接针对根因（持续下跌趋势中维持高仓位），且不改变「恐惧时买入」的核心逻辑——只在下跌趋势中限制上限。

该改动属**设计级变更**，须走 `docs/trading-discipline.md` 第 8 条流程：先改文档 → 再改代码 → 再回测验证（含样本外）→ 通过后生效。**本文档即该流程的第 1 步。**

### 1.2 v2 的两个目标

1. **修正 v1 的根因**：引入趋势过滤，**同时应用到大盘与加密两个市场**。
2. **扩展加密子系统**：把加密关联杠杆 ETF 纳入标的池，用**独立的加密贪恐指数**驱动（与大盘指数并行，互不污染）。

### 1.3 成功标准（分级目标）

| 市场 | 最大回撤目标 | 参照基准 | 说明 |
|---|---|---|---|
| **大盘** | **≤ -40%** | v1 实测 -61.53%；买入持有 TQQQ -82% | 比 v1 改善 21pp，向原目标 -35% 靠拢 |
| **加密** | **≤ -50%** | 2x BTC 合成序列 buy&hold 约 -90% | 相对基准改善约 40pp |

**不硬套同一个数字**：加密波动量级与股市不同（BTC 自身最大回撤 -84%，2 倍日复利放大后约 -90%）。用同一个 -35% 会让加密部分沦为过拟合。

明确接受：任何降仓位的择时策略在单边上行期大概率跑不赢无脑持有。本系统的价值在**避开灾难性回撤**，让你拿得住、不靠人为干预。

### 1.4 非目标（YAGNI）

- 不接券商 API 自动下单（沿用 v1）。
- 不做日内交易、不做高频。
- 不接入 coinglass 程序化 API（见 §10）。
- 不做跨市场动态资金分配（已否决，见 §7.1）。

## 3. 整体架构

### 3.1 资金结构

```
统一资金池 100%
├── 核心仓（按固定比例分给两个市场）
│   ├── 大盘核心仓 ← 大盘指数五档 × 趋势过滤系数
│   └── 加密核心仓 ← 加密指数五档 × 趋势过滤系数 → 三层递减上限
└── 弹药池（全组合共享一个，先到先得）
    ├── 大盘触发：标的指数(QQQ/SOXX/SPY) -20% / -40% / -60%
    └── 加密触发：BTC 现货 -30% / -50% / -70%
```

**为什么共享弹药池**：加密三层高度相关——BTC 崩盘时 BITX、MSTX、CONL 会**同一天**触发加仓。若各自备弹药，会在同一天同时打光并实际超配；共享池把「谁先用」变成显式规则，而不是隐性超配。

**为什么核心仓固定比例**：固定比例让「每个市场的预算上限」可预测、可解释、可回测。动态分配（波动率平价、双指数共振）参数多且实盘难以直观解释，与「管住手」的诉求相悖。

### 3.2 分层职责边界（v2）

| 层 | 职责 | 不负责 |
|---|---|---|
| `data` | 抓取、落地、对齐、缺失处理、**杠杆序列合成** | 任何因子逻辑 |
| `factors` | 单一因子 → 0-100 分（带 `market` 归属） | 因子间权重、仓位 |
| `index` | 按市场加权合成 → 各市场指数 | 仓位、交易 |
| `signal.market_signal` | 单市场：指数 + 回撤 + 趋势 → 该市场目标仓位 | 跨市场协调 |
| `signal.portfolio` | 组合级：共享弹药池 + 统一资金池 → 最终目标仓位 | 单市场五档逻辑 |
| `backtest` | 撮合、成本、评估 | 任何信号计算 |
| `dashboard` / `audit` | 展示、审计 | 任何计算 |

**硬性约定（沿用 v1 §3.4）**：`signal` 层是唯一产生仓位的层，且必须是**纯函数 + 显式传入状态**，禁止读写全局变量或文件。状态由调用方（pipeline / backtest runner）负责持久化。

### 3.3 为什么拆分 `signal` 层

v1 的 `signal` 是单市场纯函数。v2 引入共享弹药池后，两类状态的性质不同：

- **市场级**：五档映射、趋势过滤系数、分层上限 —— 只依赖该市场的数据。
- **组合级**：弹药池余额、批次释放状态 —— 跨市场竞争，依赖两个市场的信号。

混在一个函数里会让「**哪个市场的信号触发了这笔调仓**」无法回答——这恰恰是 v1 复盘时最难查清的部分。拆开后：

- `market_signal` 输出「本市场今天想要多少仓位 + 是否触发了回撤档位」
- `portfolio` 消费两个市场的输出，裁决弹药分配，产出最终目标仓位

这同时解决 v1 遗留问题 6（防抖动逻辑在 `strategy.py` 与 `signal.throttle_ok` 两处重复实现）——v2 把 clamp 统一收敛到 `portfolio` 层。

### 4.2 合成杠杆序列（双轨方案的「合成轨」）

**为什么需要**：加密 ETF 真实历史最长仅 4 年（CONL），而 v1 的 warmup 需 756 交易日（3 年）——扣掉 warmup 后仅剩 1 年可回测，且完全未覆盖 2018 熊市、2020 疫情崩盘、2022 熊市。**情绪数据的历史（8.6 年）远长于杠杆 ETF 的价格历史**，这个错配是问题根源。

**合成公式**：

```
合成日收益 = N × 底层日收益 − (产品损耗率 / 252)
合成价格   = ∏(1 + 合成日收益)
```

- `N`：杠杆倍数（加密 ETF 均为 2）
- 底层：BTC / ETH / COIN / MSTR
- 产品损耗率：**实测校准值**（见下），非费率

**日历**：合成序列建在**美股交易日历**（`Data/raw/prices.csv` 的 SPY 日期）上，先把底层 reindex 到美股交易日再算收益。这样成本按 ~252 交易日/年摊（而非 7×24 底层的 365 天/年），且保留底层的完整历史（合成轨的目的就是把回测拉长到 10 年）。

**质量门（改为「实测校准 + 强制披露」）**：

初版设计为硬质量门（偏离 < 5% 否则作废）。实施阶段用真实数据独立诊断后**推翻**了该门：

| 标的 | 真实年化 | 合成（7 天日历） | 合成（美股日历） | 反推所需年化成本率 | 校准后残留偏离 |
|---|---|---|---|---|---|
| BITX | +10.16% | +46.89% | +47.03% | **30.2%** | < 0.3% |
| BITU | −27.35% | −9.78% | −9.95% | **22.9%** | < 0.3% |
| MSTX | −65.34% | −38.87% | −38.87% | **57.9%** | < 0.3% |
| MSTU | −56.45% | −38.90% | −38.90% | **35.3%** | < 0.3% |
| CONL | −24.38% | −23.59% | −23.59% | **2.2%** | < 0.3% |

**结论**：
- **日历不是主因**（修正后偏离几乎不变）。原「日历错配」假设被推翻。
- **CONL 只需 ~2% 成本率**——这正是合理的费用+融资，说明**模型原理是对的**。
- **BITX/BITU 需要 22-30%**：它们是 **BTC 期货**产品，有展期/升水成本，模型用现货 BTC 无法捕捉。
- **MSTX/MSTU 需要 35-58%**：2x **单股互换**在超高波动标的上的融资价差 + 跟踪误差，模型无法机制化捕捉。
- **这些数字不是费用，是「模型未捕捉的机制」的等效代理。**

**因此改用「实测校准 + 强制披露」**：不硬失败，也不用假的成本率掩盖。用 `calibrate_cost_rate` 二分求「让合成累计收益等于真实 ETF 累计收益」所需的年化成本率，回填 `config.CRYPTO_PRODUCT_COST_RATE`，使合成序列复现真实产品的**已实现拖累**。校准后 `check_gate` 的残留年化偏离接近 0（远小于 5%）。

**强制披露（必须在文档和报告中明确）**：
> 本模型是「N 倍日再平衡」的机制化复现，但真实加密杠杆 ETF 的实际拖累远超其费率：BITX/BITU 持有 BTC **期货**（有展期升水成本），MSTX/MSTU 是 2x **单股互换**（融资价差在超高波动标的上极宽）。实测反推所需的等效年化成本率为 2%~58%（CONL 仅 ~2%，符合合理费用；其余远超标）。因此本模块采用**实测校准**：用真实产品在重叠区间的实际表现反推成本率，使合成序列复现真实产品的**已实现拖累**。
>
> **但这意味着**：合成轨的绝对收益是「按构造校准」出来的，**不具备预测性**；且校准基于 2022-2026 的利率与升水环境，外推到 2018-2022 存在不确定性。任何收益/回撤结论必须优先引用**真实轨**；合成轨仅用于验证策略**行为**。

`calibrated_rate` 超过 `config.CRYPTO_IMPLAUSIBLE_COST_RATE`（默认 0.15）时 `validate_against_real` 置 `warning=True`，提示该标的的合成轨属**经验校准**而非机制建模。

**合成轨的定位（必须在文档和报告中明确）**：合成序列**不是真实交易标的的历史**，它只用于验证**策略逻辑**（五档、趋势过滤、弹药档位在完整加密周期中的行为）。任何基于合成轨的收益数字都必须标注「合成」，不得与真实轨混淆。

### 4.3 拆股 / 合股处理（扩展到加密标的）

v1 §4.4 的机制**整体沿用**，并扩展到加密标的：

1. 价格序列必须**前复权**；禁止使用未复权价格参与任何计算。
2. `splits.csv` 扩展记录加密标的的拆股/合股事件。**加密 ETF 的合股风险尤其高**——2x 杠杆在长期熊市中净值快速衰减，发行方会通过合股维持价格（如反向 ETF 的归零机制）。
3. **主防线仍是数据驱动的相对偏离检测**：`|杠杆ETF单日收益 − N × 底层单日收益| > 阈值` 即中止 pipeline。
   - **阈值需针对加密重新标定**：加密日波动远大于股票，v1 的 20pp 阈值可能过紧。
   - 标定方法：在真实 ETF 与底层（BTC/COIN/MSTR）的重叠区间上，取实际偏离分布的极值并留余量。
   - **这是硬失败（fail fast）**，不是告警。
4. 加密 7×24 交易、ETF 仅美股时段交易 → **隔夜跳空是常态**，偏离检测需考虑这一点（周末与节假日的累计跳空）。

### 4.4 交易日对齐

1. 主日历：**美股交易日**（加密 ETF 只能在美股时段交易，回测成交必须用美股日历）。
2. 加密贪恐指数与 BTC 现货为 7×24 → 对齐到美股交易日时，取**该美股交易日收盘时刻之前的最新值**，避免用未来数据。
3. 缺失处理沿用 v1 §4.3：价格类不填充（NaN），指数类前向填充并记录 `stale_days`，`stale_days > 5` 时该因子当日输出 NaN。

## 5. 因子层与指数

### 5.1 大盘指数（不变）

v1 的四因子**保持不变**（已验收，|corr| 最大 0.595）：

| 因子 | 权重 | 构成 |
|---|---|---|
| F1 VIX 水位与变化率 | 30% | `0.7·z(vix_level) + 0.3·z(vix_chg5)`，反转 |
| F2 波动率期限结构 | 20% | `VIX/VIX3M` 比值，5 日均线，反转 |

| F4 广度代理 | 20% | RSP/SPY、QQQ/SPY 60 日变化率 + 均线宽度 |

### 5.2 加密指数（新增）

**加密指数 = CF1 贪恐指数 + CF2 价格因子**，权重 **50% / 50%**（先验值，**不做全样本优化**）。

#### CF1 加密贪恐指数（权重 50%）

- 原始量：alternative.me 的 0-100 值（高分 = 贪婪，**方向与自建指数一致，无需反转**）。
- 归一化：滚动 3 年（756 交易日）百分位。
- **为什么还要归一化**：alternative.me 的值本身已是 0-100，但它是**绝对刻度**。2018 年"贪恐 30"与 2024 年"贪恐 30"的市场含义不同（加密市场的情绪中枢在漂移）。滚动百分位把它转为「相对当下环境的情绪位置」，与 v1 §5.3 的跨周期可比性要求一致。

#### CF2 BTC 价格因子（权重 50%）

四个子项，各自归一后**等权**平均（与 v1 F3 结构对称）：

| 子项 | 定义 | 方向 |
|---|---|---|
| 动量 | BTC 的 20 日与 60 日收益率 | 正向（高分=贪婪） |
| RSI | BTC 的 RSI(14) | 正向 |
| 回撤 | 距 52 周（252 交易日）最高收盘价的回撤幅度 | 反转（回撤大=恐惧） |
| 波动率 | BTC 的 20 日已实现波动率（年化） | 反转（波动大=恐惧） |

**输入口径约束（沿用 v1 §4.5 约束 1，这是红线）**：CF2 的输入必须是 **BTC 现货**，**禁止使用 BITX 等杠杆 ETF 自身价格**。理由与 v1 完全相同——杠杆 ETF 价格含年化数十个百分点的波动率拖累，会把损耗系统性误读为恐惧。

#### 交叉校验

CF1（贪恐）与 CF2（价格）来自**完全独立的两个源**，因此可以做交叉验证：

- 若长期 |corr| < 0.2，说明两者在讲不同的故事 → **输出告警**供人工复核（可能意味着贪恐指数的口径与价格严重脱节）。
- 这是 v1 单源自建指数不具备的能力（v1 的四个因子都源自价格/波动率族）。

### 5.3 归一化与合成

- **归一化**：沿用 v1 的**滚动 3 年百分位**（`rank_window = 756`），禁止用固定阈值或全样本统计量。
- **合成**：`index = Σ(wᵢ × scoreᵢ) / Σ wᵢ`，仅对当日有效因子求和；有效因子数 < 2 时输出 NaN。
- **平滑**：v1 不平滑（`smoothing_days = 1`），v2 沿用。
- **warmup**：756 交易日。加密合成轨的起点由底层资产历史决定（BTC 现货可回溯至 2018 年前，满足 8.6 年窗口）。

## 6. 信号层

### 6.1 趋势过滤（v2 的核心修正，两个市场都加）

**触发**：标的指数的收盘价 < 其 200 日简单移动平均。

**动作**：该市场的核心仓上限 **× 0.5**。

| 市场 | 趋势判断基准 |
|---|---|
| 大盘 | QQQ（大盘核心仓的主指数） |
| 加密 | BTC 现货 |

**设计要点**：

1. **只限制上限，不改变五档逻辑**——牛市（指数在均线上方）时仓位完全不受影响。这是选择「趋势过滤」而非「降低核心仓上限」的原因：后者会把「下跌趋势」与「震荡回调」一起误伤。
2. **基准用无杠杆标的**，与 v1 §4.5 约束 2 一致（杠杆 ETF 自身回撤含损耗，会"自然"触发）。
3. **参数 `trend_ma_days = 200`**，不做全样本优化。
4. **必须输出贡献度归因**（见 §8.4）：开关趋势过滤的回撤差异，量化这项改动的实际价值。若贡献度接近零，说明修正无效，应回到验收报告的选项 A（降低核心仓上限）。

### 6.2 五档映射（沿用 v1 §7.2）

> **v2.1 修订（2026-09-22）**：`CORE_CAP` 由 70% 下调至 **45%**（见 §7.1）。
> 本表按新上限重算。变更流程与验证见 `docs/trading-discipline.md` 第 12 条。

| 指数区间 | 档位 | 饱和度 | 大盘核心仓（上限 31.5% 时） | 加密核心仓（上限 13.5% 时） |
|---|---|---|---|---|
| 0-20 | 极度恐惧 | 100% | 31.5% | 13.5% |
| 20-40 | 恐惧 | 75% | 23.6% | 10.1% |
| 40-60 | 中性 | 50% | 15.8% | 6.8% |
| 60-80 | 贪婪 | 25% | 7.9% | 3.4% |
| 80-100 | 极度贪婪 | 0% | 0.0% | 0.0% |

趋势过滤生效时，上表的核心仓再 **× 0.5**（大盘上限 31.5% → 15.75%，加密 13.5% → 6.75%）。

### 6.3 加密三层递减上限（新增）

加密核心仓在按五档算出后，再按标的所属层限制：

> **v2.1 修订（2026-09-22）**：三层上限由 100% / 70% / 50% 收紧至 **80% / 50% / 30%**。
> 依据是真实轨实测最大回撤 **-85% ~ -99.6%**（MSTX 接近净值归零）。见 §12 风险 11。

| 层 | 标的 | 上限（相对加密核心仓） | 理由 |
|---|---|---|---|
| BTC 纯 Beta | BITX / BITU | **80%** | 只承担币价风险。设 80% 上限 ⇒ **强制 ≥20% 分散到 BTC 层之外** |
| 币股高 Beta | MSTX / MSTU | **50%** | 叠加融资能力与 NAV 溢价风险（MSTR ≈ BTC 资产负债表 Beta）；实测最大回撤 **-99.6%** |
| 币股经营 Beta | CONL | **30%** | 再叠加经营与监管风险（价格 Beta + 成交量 Beta + 监管 Beta）；实测最大回撤 **-95.4%** |

**绝对上限**（加密核心仓满仓值 = 45% × 30% = 13.5%）：BTC 层 10.8% / 高 Beta 层 6.75% / 经营 Beta 层 4.05%。

**三层是互斥预算，不是叠加**——加密核心仓总额不得超过 13.5%，无论分给几层。

**层内分配**：v2 **等权**（如 BTC 层 BITX/BITU 各半）。与 v1 的「v1 等权、v2 再上因子分加权」保持一致节奏。

**这个分层的依据**：币股已摆脱统一的 Crypto Beta。MSTR 是 BTC 高 Beta 载体、COIN 是复合 Beta、CRCL/HOOD/FIGR 更接近现实经营现金流。**风险越靠「间接」的一端，同样的仓位对应的实际风险越大**——递减上限把这个不对称显式化。

### 6.4 共享弹药池（新增，组合级）

**池子一个，先到先得**，按日推进状态。

| 市场 | 回撤基准 | 触发档位 | 每批释放 |
|---|---|---|---|
| 大盘 | QQQ / SOXX / SPY 的滚动 52 周最高 | -20% / -40% / -60% | 各 **6.67%** |
| 加密 | BTC 现货的滚动 52 周最高 | **-30% / -50% / -70%** | 各 **6.67%** |

**池子上限 `AMMO_CAP = 20%`**（每批 `AMMO_CAP / 3` ≈ 6.67%）。
沿革：v2 30% → v2.2 12% → **v2.4 20%**（依据见 `docs/trading-discipline.md` 第 12.6 / 12.7 条）。

**为什么加密档位加宽**：2x BTC ETF 从高点回撤 20% 是**几个月就会发生一次的常态**（2024 年出现多次），而 TQQQ 回撤 20% 往往对应真正的市场危机。若加密沿用 -20%，共享池会被频繁抽干，**大盘真正崩盘时反而没弹药**——这正好破坏了共享池的设计初衷。

**冲突处理（同一日两市场同时触发）**：

```
优先级 = 该市场当前回撤幅度 / 该市场「当前待释放批次」的阈值
```

**口径说明**：分母是**该市场当前待释放的那一批**的阈值，不是全部三档。例如大盘已释放第 1 批、当前待释放第 2 批（阈值 40%），而加密尚未释放任何批次（当前待释放第 1 批，阈值 30%），此时大盘回撤 45% → 优先级 45/40 = 1.125，加密回撤 35% → 优先级 35/30 = 1.167，**加密优先**。

比值大者优先。理由：比值表达「相对自身当前档位，谁跌得更极端」，比绝对值公平（加密天然跌得多，用绝对值会让加密永远优先）。

**平局处理**：优先级相同时，**大盘优先**。理由：大盘标的（TQQQ/SOXL/UPRO）的流动性显著优于加密 ETF，且大盘崩盘往往伴随系统性风险，先补大盘更符合风险管理的直觉。

**其他规则**（沿用 v1 §7.3）：

- 每批**只释放一次**，状态持久化在 `Data/state.json`。
- 弹药释放后**长期持有**，不因回撤修复而卖出，只受极端规则管理。
- 回撤基准用**滚动窗口**而非历史最高点，避免历史极值导致此后长期"满弹药"。
- **弹药池一旦耗尽即成为「永久仓位下限」**（实测 2018-11-16 三批释放完毕后，弹药恒定
  占比达 **7.8 年**）。这不是缺陷，是上一条「长期持有」的**必然推论**——因此 `AMMO_CAP`
  必须按**永久仓位**（而非临时储备）的标准设风险预算：它**不受趋势过滤保护**，
  崩盘中会吃满跌幅。v2.2 据此由 30% 下调至 **12%**。

### 6.5 极端规则

#### 大盘：沿用 v1 §8（已验收）

- **极贪熔断**（指数 ≥ 85）：仓位减至 25% 底仓，禁买 3 交易日，条件解锁（指数 < 60 / 标的反弹 ≥ 10% / 指数自峰值回落 ≥ 15 点）。

  **底仓语义（消歧，实施中发现并修正）**：底仓是**替换**五档饱和度，**不是取 min**。

  与加密极贪档位是**同一类缺陷**：熔断在指数 ≥85 触发，而五档在 ≥80 时已给饱和度 0（清仓）。若写成 `min(core, full × 0.25)`，熔断永远对着 0 取最小，「25% 底仓」成为**死代码**——而 v1 §8.1 的原话是「减至 25% 底仓（**不清仓**——避免完全踏空后续反弹）」，语义就是替换。

  **比例基准**：v1 是单市场，25% 指总仓位；v2 有两个市场，故 25% 相对**该市场核心仓的满仓值**（与加密极贪档位一致）。即大盘熔断时核心仓 = `CORE_CAP × MARKET_CORE_RATIO[us_equity] × 趋势系数 × 0.25`。
- **极恐加仓**（指数 ≤ 10）：核心仓打满 + 允许提前释放下一批弹药，84 自然日冷却。

#### 加密：极贪分批减仓（新增）

加密的极贪区间**可持续数月**（2017、2021、2024 的极贪都持续很久），一次性清仓极可能踏空后半段主升浪。因此改为**分批递减**：

| 触发 | 动作（比例基准见下方说明） |
|---|---|
| 指数 ≥ 85 | 减至 **2/3** |
| 指数 ≥ 90 | 再减至 **1/3** |
| 指数 ≥ 95 | 再减至 **1/4** |

**比例基准定义（消歧）**：上表比例统一相对**加密核心仓的满仓值**——即「五档 100% 饱和度 × 加密核心仓上限」，若趋势过滤生效则再 × 0.5。这与 v1 的 `extreme_greed_floor = 0.25`（熔断后底仓 25%）语义一致，保证两市场规则可类比。

**与五档的关系（消歧，实施中发现并修正）**：档位 > 0 时**替换**五档饱和度（即设一个下限），**不是与之相乘**。

原因是五档映射的 `ZONE_EDGES = [20, 40, 60, 80]` 在指数 ≥80 时已给**饱和度 0.0**（清仓），而本节的档位在 ≥85 才触发——若写成相乘，档位永远对着一个**已经为 0** 的仓位做乘法，成为**死代码**，直接违背本节开头「不一次性清仓、分批递减」的初衷。

正确语义：`core = 加密核心仓满仓值 × 趋势系数 × 档位系数`（档位 > 0 时），档位 = 0 时沿用五档饱和度。这样指数 86 时仓位是满仓的 2/3 而非 0。

- 每档**只触发一次**，状态持久化。
- 解锁：指数回落至 < 60 时**逐档恢复**（95 → 90 → 85 依次解除，而非一次性恢复满仓）。
- **极恐加仓**：沿用大盘规则（核心仓打满 + 提前释放弹药），但**加密的极恐触发线需实测标定**——加密指数分布与大盘不同，沿用 10 可能过严或过松。

### 6.6 规则优先级

```
趋势过滤上限约束  >  极端规则（熔断/分批减仓/极恐）  >  五档映射  >  分层上限  >  共享弹药池
```

**说明**：趋势过滤置于最高优先级——它是**风险控制**，而极端规则是**机会捕捉**。在下跌趋势中，即使指数极恐也不应突破趋势过滤给出的上限。这一点与 v1 不同（v1 无趋势过滤），是 v2 的实质变化，**需在回测中重点验证**。

极端规则触发时，**豁免** §6.7 的防抖动约束。

**v2 的改进**：v1 遗留问题 6 指出防抖动逻辑在 `strategy.py` 与 `signal.throttle_ok` **两处各实现一遍**。v2 把 clamp **统一收敛到 `portfolio` 层**，`strategy.py` 只读最终目标仓位，不再自行判断。

> 依据见 `docs/trading-discipline.md` 第 12.2 条。

**注意**：`MARKET_CORE_RATIO` 的分母是 **`CORE_CAP`（核心仓上限）**，不是总资金。若误按总资金理解，会得出 70%+30%+30% = 130% 的错误结果。

**关于 70/30 的性质**：这是**先验值**，不是标定结果。实施阶段必须做**敏感性测试**（60/40、70/30、80/20 三档），结果写入回测报告。

**禁止用全样本优化得到"最优"分割比例**——那会直接过拟合。若敏感性测试显示结论对该比例高度敏感，说明策略本身不稳健，应优先怀疑策略逻辑，而非继续调比例。

**已否决的方案**（记录备查）：

- **波动率平价动态分配**：按两市场波动率倒数分配预算。风险更均衡，但参数多、实盘时难以直观解释系统为什么这么配仓。
- **双指数共振加仓**：两指数共同决定总仓位上限。能捕捉共振，但组合规则复杂，容易出现难解释的仓位。

### 7.2 目标仓位计算

```
各市场核心仓 = 五档饱和度 × 核心仓上限 × 趋势过滤系数
大盘标的权重 = 反比波动率 w_i ∝ 1/σ_i（σ 用无杠杆底层，滚动 252 日）  ← v2.3
各标的仓位   = target_position × w_i        （Σw_i = 1，故加总仍 = target_position）
加密三层     = 加密核心仓 × 该层上限比例，层内等权
组合核心仓   = 大盘核心仓 + 加密核心仓
组合弹药仓   = 共享池已释放批次 × 4%
target_position = 组合核心仓 + 组合弹药仓
```

> **v2.3 修订（2026-09-22）**：`us_equity` 内由**等权**改为**反比波动率权重**。
> 等权的隐含假设（三标的风险相同）被实测否定：买入持有年化波动率
> **SOXL 1.03 / TQQQ 0.67 / UPRO 0.54**。等权下 SOXL 的风险贡献达 **46%**
> （权重仅 33%），**超配 13pp**，它单独主导了 `us_equity` 的回撤。
> 规则见 `docs/trading-discipline.md` 第 4C 条，变更记录见第 12.5 条。

> **v2.3 同时修正回测口径**：原 `backtest-v2` **逐标的独立**跑，把整份
> `target_position` 压到单一标的，测的是「假设全仓某一只」的**单标的最坏值**，
> **不是实际组合**。新增**组合级**口径（Σ 各标的加权），
> **验收判定以组合级为准**，逐标的仅用于识别是哪个标的在拖累。

## 10. coinglass 探测结论（决定：不接入，人工对照）

### 10.1 探测结论（2026-09-21）

用户指定 `https://www.coinglass.com/zh/pro/i/FearGreedIndex`。做了完整逆向探测：

| 探测项 | 结果 |
|---|---|
| 页面数据加载方式 | Next.js 客户端加载，`__NEXT_DATA__` **仅含 i18n 翻译，不含数据** |
| 前端 API 域名 | `capi.coinglass.com` / `fapi.coinglass.com`（从 23 个 JS chunk 中挖出） |
| 路由结构 | `/api/index/<指标名>`，共挖出 **435 个端点** |
| 贪恐端点 | `/api/index/fearGreed` —— 返回 **HTTP 200** |
| **返回内容** | `{"code":"0","msg":"success","success":true}`，**43 字节空壳，无 data 字段** |
| **对照验证** | 页面上**明确有数据**的端点（`cgdi`、`puellMultiple`、`stockFlow`）返回**完全相同的 43 字节空壳** |
| 反爬 header 尝试 | `cache-ts`(ms/s) / `language` / `Referer` / `Origin` / `X-Requested-With` 全部无效 |
| POST 方式 | 返回 `{"code":"40001","msg":"Server Error","success":false}` |
| 官方 API | `open-api.coinglass.com/public/v2/...` → **500**；`open-api-v4` → **404** |

**结论**：连页面上确定有数据的端点也返回同样的空壳，说明这不是端点写错，而是 coinglass 有**统一的鉴权层**（登录态或加密签名），对所有未授权请求统一返回伪装成 200 的空响应。**无法通过普通 HTTP 请求绕过。**

### 10.2 替代源：alternative.me

| 项 | 结果 |
|---|---|
| 可用性 | ✅ 免费、**无需 API key**、开箱即用 |
| 历史深度 | **3151 条日度数据，2018-02-01 起（8.6 年）** |
| 与合成轨的匹配 | 回测窗口完全对齐 |
| 指标性质 | 同类聚合情绪指标（0-100 加密市场情绪），但**权重构成与 coinglass 有差异** |

### 10.3 决策：alternative.me 为主 + coinglass 人工对照

1. **系统用 alternative.me 自动跑全链路**，零鉴权风险。
2. **仪表盘保留 coinglass 人工对照栏**（复用 v1 §15.3 的 `external_index.csv` 机制）：你每天从 coinglass 页面看数值后手填。
3. **coinglass 数值永远不参与仓位计算**，仅用于事后复盘对照（例如复盘时回看："系统按 alternative.me 减仓那天，coinglass 显示什么位置"）。
4. 两者背离超过 30 点时**不触发任何告警或动作**，仅作为复盘观察点。
5. **探测脚本已删除，不纳入交付物**（含逆向细节）。本节保留结论性记录。
