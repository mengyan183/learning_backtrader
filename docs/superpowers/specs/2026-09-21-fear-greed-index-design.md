# 贪婪恐惧指数交易纪律系统 — 设计文档

- 日期：2026-09-21
- 状态：待用户评审
- 范围：回测研究 + 可视化仪表盘（不含券商 API 自动下单）

---

## 1. 背景与目标

### 1.1 要解决的问题

两个真实痛点，缺一不可：

1. **管不住手**：频繁的人为买入卖出，情绪驱动，缺乏一致性。
2. **没有成文的交易规范**：现有规则散落在经验里（如"跌 20% 加仓"），无法复盘、无法约束。

### 1.2 目标

构建一个自建的多因子**贪婪恐惧指数**（0-100，高分=贪婪），并以该指数为唯一决策源，输出明确的仓位指令，配合成文的交易纪律规范与违规审计，把"人的裁量权"压缩到"只负责执行"。

### 1.3 成功标准（回撤优先）

| 指标 | 目标 |
|---|---|
| 最大回撤 | 从买入持有 TQQQ 的 -80% 级别压到 **-35% 以内** |
| 总收益 | **允许跑输**买入持有 TQQQ |
| 换手次数 | 显著低于人工交易频率（约束见 §9） |

明确接受：任何降仓位的择时策略在 2010-2025 这段 TQQQ 单边上行期大概率跑不赢无脑持有。本系统的价值在**避开 -80% 级别的回撤**，让你拿得住、不靠人为干预。

**必须在动工前知道的代价（§4.5 实测数据）**：杠杆 ETF 存在数学必然的损耗——SOXL 年化 **46.81%**、TQQQ 年化 **20.22%**、UPRO 年化 12.02%，且随持有期线性累积（TQQQ 持有 3 年中位损耗 -58.93%）。本策略"恐惧时满仓"意味着在**波动率最高的时期**持有**损耗最贵的产品**。因此本系统的目标不是"打败买入持有"，而是"用可接受的收益折让，换取能把回撤压到可承受范围"。若计入损耗后期望收益仍不理想，正确的应对是降低仓位或改用无杠杆标的，**而不是加大调参力度**。

### 1.4 非目标（YAGNI）

- 不接券商 API 自动下单。
- 不做日内交易、不做高频。
- v1 不做多标的轮动（只做等权持有 2-3 只核心杠杆 ETF）。
- v1 不集成外部付费贪恐指数（见 §15）。

## 3. 整体架构

### 3.1 架构方案

**pandas 预计算全链路 + backtrader 只做执行与评估。**

理由：
- 因子调试成本极低——每个因子是纯 pandas 函数，可单独画图、单独算 IC。
- 前视偏差天然可控——所有因子统一在一处 `shift` 后参与决策。
- backtrader 用在其擅长处——撮合、佣金、滑点、多标的、分析器。
- 仪表盘与回测数据同源——不需要两套逻辑。

被否决的方案：
- 单文件全塞进 `Strategy`：backtrader 的 indicator 面向 OHLCV，承载 Put/Call、广度这类非价格序列极其别扭，且因子无法脱离回测验证。
- 因子用 backtrader indicator 实现的分层：调试一个因子要跑完整回测。

### 3.3 数据流

```
raw 数据（prices.csv / putcall.csv）
   │
   ▼ loader       统一交易日索引 → 宽表（每列一个序列）
   ▼ factors      每个因子输出 0-100 情绪分（高分=贪婪）
   ▼ index        加权合成 → fg_index (0-100)
   ▼ signal       五档映射 + 弹药池 + 极端规则 + 防抖动 → 目标仓位（含状态机）
   ▼ pipeline     落地 features.csv
   ▼ backtest     backtrader：T 日收盘算信号，T+1 开盘执行
   ▼ dashboard    HTML 仪表盘 + 指标表
   ▼ audit        trade_log.csv vs 指令 → 违规报告
```

### 3.4 分层职责边界

| 层 | 职责 | 不负责 |
|---|---|---|
| `data` | 抓取、落地、对齐、缺失处理 | 任何因子逻辑 |
| `factors` | 单一因子 → 0-100 分 | 因子间权重、仓位 |
| `index` | 因子加权 → fg_index | 仓位、交易 |
| `signal` | 指数 + 回撤 → 目标仓位（纯函数 + 显式状态） | 下单、撮合 |
| `backtest` | 撮合、成本、评估 | 任何信号计算 |
| `dashboard` / `audit` | 展示、审计 | 任何计算 |

**硬性约定**：`signal` 层是唯一产生仓位的层，且必须是**纯函数 + 显式传入状态**，禁止读写全局变量或文件。状态由调用方（pipeline / backtest runner）负责持久化。这是保证回测与日常运行逻辑完全一致的关键。

### 4.2 落地格式

**实际落盘（2026-09-21 已下载完成）**：

| 文件 | 内容 | 规模 |
|---|---|---|
| `Data/raw/prices.csv` | 9 个标的复权 OHLCV 长表 `date,symbol,open,high,low,close,volume` | 22624 行 / 1.2MB |
| `Data/raw/vix.csv` | VIX 日线 `date,open,high,low,close` | 9276 行 / 1990 起 |
| `Data/raw/vix3m.csv` | VIX3M 日线 | 4276 行 / 2009 起 |
| `Data/raw/putcall_total.csv`、`putcall_equity.csv` | CBOE Put/Call（**止于 2019-10，仅作参考**） | 3253 行 |
| `Data/raw/splits.csv` | 拆股/合股事件 `symbol,date,ratio,source,verified` | **待编码阶段生成** |

**版本管理策略**：`Data/raw/` **入库**（约 2MB）。理由：回测结论的可复现性优先于仓库体积，且数据源是单一第三方接口，存在变更风险。管道产物（`features.csv`、`state.json`）仍不入库——它们可从原始数据完全重新生成。

**格式规则**：
- 日期一律规范化为 `YYYY-MM-DD` 并**升序**存储。抓取源的原始格式可能不同（Nasdaq 返回 `MM/DD/YYYY` 且降序），由 `fetch.py` 统一转换。
- 增量更新：读取本地最大日期，只抓缺失区间，追加后整体去重排序。
- 幂等性：重复执行 `fetch` 不产生重复行。

**工具脚本**：`scripts/fetch_market_data.py` 为设计阶段的可行性验证脚本，已验证上述数据源全部可用；编码阶段由 `fg_system/data/fetch.py` 正式实现（可直接复用其请求与解析逻辑）。

### 4.3 交易日对齐与缺失处理

1. 以**交易标的的交易日**为基准索引（用 SPY 的交易日作为主日历）。
2. 各序列左连接到主日历。
3. 价格类缺失（停牌/无数据）：**不做前向填充**，标记为 NaN，对应因子当日输出 NaN。
4. Put/Call 缺失：前向填充，同时记录 `stale_days`（连续填充天数）。
5. **`stale_days > 5` 时该因子当日输出 NaN**（等价于权重置零），由 §5.4 的权重重归一化机制处理，而不是静默沿用陈旧值。
6. 回测起点前需满足**最长滚动窗口 warmup**（见 §5.5），warmup 期内不产生信号。

### 4.4 拆股 / 合股 / 分红处理（杠杆 ETF 关键约束）

**问题**：多倍杠杆 ETF 是高波动品种，发行方会通过拆股（split）或合股（reverse split）把价格维持在便于交易的区间。TQQQ、SOXL、UPRO 历史上都发生过拆股。**未复权的价格序列在拆股日会出现剧烈的假跳空**（例如 2:1 拆股表现为单日 -50%），会污染整条链路：

| 受影响环节 | 后果 |
|---|---|
| F3 价格因子（动量 / RSI / 回撤 / 波动率） | 拆股日被识别为"极度恐惧"，产生假信号 |
| 弹药池回撤基准（52 周最高价） | 拆股前的真实高点被当成"从未达到"，或拆股后误判为深度回撤，触发错误的弹药释放 |
| 回测成交与盈亏 | 持仓份额与成本价全部错乱 |
| 熔断 / 极恐触发 | 假信号可能触发熔断清仓或极恐加仓 |

**强制规则：**

1. **价格序列必须复权**，口径为**前复权**（以最新价格为基准，同时处理拆股与分红）。理由：最新价格保持为真实市场价，便于与行情软件对照；收益率序列与后复权等价。
2. **禁止使用未复权价格参与任何因子计算或回测。**
3. **拆股记录表** `Data/raw/splits.csv`：`symbol,date,ratio,source,verified`。
   - **数据来源（实测结论）**：Nasdaq 全站**不暴露**拆股事件——`/api/quote/{s}/splits` 返回 404；`/api/quote/{s}/dividends` 返回的 23~57 行 `type` 全为 `Cash`，无拆股类型；SOXL/UPRO 等 NYSE Arca 标的直接返回 "Dividend History for Non-Nasdaq symbols is not available"。因此拆股记录**只能人工维护**（`source=manual`），核对后置 `verified=1`。
   - **因此主防线是第 4 条的数据驱动检测，而不是本表**——本表是人工补充的精确校验，覆盖能力受限于人工维护的完整性。
   - 该表是校验基准，也是将来换数据源时的对照依据。
   - **`ratio` 语义**：`ratio > 1` 为拆股（2:1 记 `2.0`），`ratio < 1` 为合股（1:5 记 `0.2`）。**合股与拆股同等对待，都必须记录**——合股在价格上表现为暴涨跳空，同样会污染因子。
4. **异常跳变检测（强制，每次 pipeline 运行都执行）**：
   - **主检测（相对偏离）**：对每个杠杆 ETF 计算 `|杠杆ETF单日收益 − N × 标的单日收益|`，超过 `split_deviation_threshold`（默认 **20 个百分点**）即**中止 pipeline 并报错**。
   - **辅助检测（绝对兜底）**：检测 **`|N × 标的单日收益|`** 是否超过 `split_jump_threshold`（默认 **70%**），即标的自身单日涨跌超过约 23.3% 时兜底拦截。**注意兜底对象是"3×标的"一侧，不是杠杆 ETF 自身**——对杠杆 ETF 自身套用绝对阈值会误杀真实大涨（见下）。
   - **阈值修正记录（两次，均基于实测）**：
     - 初版用"杠杆 ETF 单日 ±40%"作阈值 → **被证伪**：SOXL 在 2025-04-09 真实上涨 **+54.79%**（同日标的 SOXX +18.57%，3× = 55.71%，偏离仅 0.92pp），会被误判中止。
     - 二版用"相对偏离 15pp" → **也被证伪**：全区间实测最大真实偏离为 **16.46pp**（SOXL 2020-03-17，+9.94% vs 3×SOXX +26.40%，标的 SOXX 当日 +8.80%、SPY +5.40%，确为真实熔断期数据），0.15 会导致全区间运行必报错。
     - 最终定 **20pp**：对 16.46pp 留有余量，同时对拆股仍有充足判别力（2:1 拆股偏离 50pp、1:5 合股偏离 150pp）。
   - **这是硬失败（fail fast），不是告警**——宁可停下来人工确认，也不能让假信号进入决策链。
5. **拆股连续性测试（单元测试，见 §14.6）**：对 `splits.csv` 中每个事件，检查复权后拆股日前后价格是否连续（跳变 < 5%）。这是防回归测试，防止将来换数据源时复权逻辑失效。
6. **分红**：由前复权统一处理，不单独建模。
7. **成交量**：拆股会导致成交量阶跃（份额数变化）。v1 的四个因子**不使用成交量**，因此无需调整。**若将来新增量能类因子，必须先对成交量做拆股调整**（乘以拆股比例），否则会引入假信号。
8. **数据健康检查报告**：pipeline 每次运行输出各标的的日期范围、缺口天数、异常跳变核对结果、拆股事件核对状态。发现未核对的新拆股事件即中止。

**数据现状（2026-09-21 实测）**：

- 既有 `Data/tqqq_history.csv`（2016-01-13 ~ 2026-01-12，2514 行）**已复权**，与 Nasdaq 官方 API 逐日数值完全一致，确认其来源即 Nasdaq。全表仅 4 个超过 ±25% 的跳变，全部对应真实市场事件（2020-03-12/13/16 疫情熔断、2025-04-09 关税暂缓）。
- 已按本文档口径重新下载并落盘：`Data/raw/prices.csv`（9 个标的 × 2514 行，2016-09-19 ~ 2026-09-18）、`vix.csv`（9276 行，1990 起）、`vix3m.csv`（4276 行，2009 起）。
- 全量异常跳变扫描结果：**仅 SOXL 2025-04-09 的 +54.79% 一处**，经核对为真实杠杆效应（标的 SOXX +18.57%），非拆股伪影——这直接促成了第 4 条阈值的修正。

### 4.5 杠杆 ETF 损耗（本设计的核心约束之一）

**运行原理**：杠杆 ETF 的合约目标是"标的指数**日收益率**的 N 倍"，通过**每日再平衡**维持。它跟踪的是日收益，不是长期收益。这个机制产生两个独立且必须区分的损耗。

#### ① 波动率拖累（数学必然，与发行方无关）

标的日收益为 `r_i` 时，杠杆 ETF 的 T 日累计收益 = `∏(1 + N·r_i) − 1`，而"N 倍线性收益" = `N × (∏(1 + r_i) − 1)`。两者之差即波动率拖累。连续时间近似下：

```
年化波动率拖累 ≈ N(N−1)/2 × σ²        （N = 3 时 ≈ 3σ²）
```

**实测验证（2016-09-19 ~ 2026-09-18，约 10 年）**：

| 杠杆 ETF | 标的 | 标的年化 σ | 波动率拖累/年 | 理论 3σ² | 产品损耗/年 | **合计/年** |
|---|---|---|---|---|---|---|
| TQQQ | QQQ | 22.5% | **12.00%** | 15.2% | 8.22% | **20.22%** |
| SOXL | SOXX | 34.8% | **37.86%** | 36.3% | 8.95% | **46.81%** |
| UPRO | SPY | 18.0% | **8.08%** | 9.7% | 3.95% | **12.02%** |

理论公式与实测高度吻合（SOXL：理论 36.3% vs 实测 37.86%），说明**这个损耗是数学必然，无法通过挑选产品规避**。

#### ② 产品损耗（费用 + 融资成本 + 跟踪误差）

"每日再平衡的 3 倍理论收益"与"实际 ETF 收益"的差额。3 倍杠杆需借入 2 倍资金，**融资成本随利率变化**，这是 2022-2023 加息期损耗加剧的主因。实测：TQQQ 8.22%/年、SOXL 8.95%/年、UPRO 3.95%/年。

#### 损耗与持有期的关系（TQQQ 相对 3 倍线性收益，滚动持有实测）

| 持有期 | 中位损耗 | 均值损耗 |
|---|---|---|
| 1 个月 | -0.70% | -0.69% |
| 3 个月 | -2.51% | -2.20% |
| 6 个月 | -5.79% | -5.12% |
| 1 年 | **-12.99%** | -8.45% |
| 2 年 | **-29.77%** | -19.40% |
| 3 年 | **-58.93%** | -33.48% |

**结论：短期持有的损耗可忽略，长期持有的损耗是灾难性的。** 持有 3 年 TQQQ，中位损耗接近 59%。

#### 对设计的四条强制约束

1. **情绪因子绝对禁止使用杠杆 ETF 自身价格。**
   决定性论据：若标的横盘一年（市场情绪中性，QQQ 收益 0%），TQQQ 仍会因损耗下跌约 **20.22%**。用 TQQQ 自身价格计算 RSI / 动量 / 回撤，会把"损耗"系统性误读为"恐惧"，产生持续的错误买入信号。
   → 所有情绪因子（F1–F4）的输入必须是**标的指数 / 正股 ETF**（QQQ、SOXX、SPY 及广度标的）。
   → 杠杆 ETF 价格仅用于三处：回测成交价、损耗归因计算、实际持仓市值。

2. **弹药池回撤基准必须用标的指数，不能用杠杆 ETF 自身。**（**已确认采纳**，2026-09-21）
   两个理由：① 杠杆 ETF 自身回撤含损耗，长期会"自然"触发，与市场情绪无关；② 3 倍杠杆下标的跌 7% 即表现为 -20%，三批弹药会被过快耗尽。用标的指数口径，-20% / -40% / -60% 才对应真实的熊市深度。
   → 实操含义：你原有的"看 TQQQ 跌 20% 加仓"习惯，在本系统中改为**看 QQQ/SOXX/SPY 跌 20%**。同样的市场深度下，TQQQ 实际可能已跌 50%+，所以触发频率会明显低于你的旧习惯。

3. **回测必须输出损耗归因**（见 §11.6），把"波动率拖累"与"产品损耗"分开列出。否则无法判断策略收益是被市场打败的，还是被产品损耗吃掉的。

4. **波动率门控：v1 只观测，不加规则**（2026-09-21 确认）。
   损耗 ∝ σ²，因此**高波动期持有杠杆 ETF 的成本急剧上升**。这与"恐惧时满仓"存在内在张力——恐惧期往往就是高波动期。

   **张力的具体形态**：真正的风险场景不是"大跌"（大跌后常有暴力反弹——2020 年 TQQQ 全年 +100%，损耗再高也值得），而是**"高波动但无趋势"的震荡市**——市场剧烈震荡使恐惧指数持续低迷、策略持续满仓，却拿不到反弹收益，损耗成为纯损失。

   **v1 处理方式**：
   - 仪表盘输出"当前损耗速率" = `3 × σ²(20日，年化) + 产品损耗率`，供人工感知。
   - 回测输出损耗归因表（§11.6）。
   - **不设任何波动率规则**——先用真实回测数据量化损耗的实际影响，再决定是否加规则。避免在没有数据支撑时凭直觉加参数，那是过拟合的典型入口。

   **被否决的备选方案（记录备查，可在 v2 用回测数据重新评估）**：
   - *波动率门控*（波动率 > 30% 时核心仓上限 70% → 50%）：与"恐惧时加仓"直接对冲——恐惧期波动率必然高，规则会退化为"恐惧时反而减仓"，削掉策略核心逻辑。
   - *高波动期换成无杠杆标的*（TQQQ → QQQ）：保持市场暴露且免损耗，但反弹时收益被削弱，且回测与执行复杂度显著上升。

## 5. 因子层

### 5.1 统一接口

```python
class Factor:
    name: str

    def raw(self, df) -> pd.Series:
        """原始值，索引为交易日"""

    def score(self, df) -> pd.Series:
        """0-100 情绪分，高分 = 贪婪；缺数据处返回 NaN"""
```

约束：
- 因子是**纯函数**，无副作用，不读写文件。
- 因子只允许访问传入 `df` 中 **≤ 当前日期** 的数据（见 §10 前视偏差红线）。
- 每个因子必须能独立运行并被单独画图验证。

### 5.2 因子定义

#### F1 VIX（先验权重 30%）

- 原始量：`vix_level` 与 `vix_chg5`（VIX 5 日变化率）。
- 合成原始分：`raw = 0.7 * z(vix_level) + 0.3 * z(vix_chg5)`，其中 `z` 为滚动 3 年（756 交易日）百分位。
- **反转**：VIX 高 = 恐惧 = 低分，故 `score = 100 * (1 - pct_rank(raw))`。
- 数据源：CBOE cdn `VIX_History.csv`（自 1990 起，日频完整）。

#### F2 波动率期限结构（先验权重 20%）

**原设计为 CBOE 权益 Put/Call 比率，但实测发现 CBOE 官方 Put/Call CSV 文件已停更于 2019-10-04**（`totalpc.csv` / `equitypc.csv` / `indexpc.csv` 均止于该日期），无法覆盖当前样本期。改用**波动率期限结构**：

- 原始量：`VIX / VIX3M` 比值（VIX3M 为 3 个月期 VIX）。
- 含义：比值 > 1 表示短期恐慌高于中期（期限结构倒挂），是市场承压的经典信号；比值 < 1 为正常状态。
- 先做 5 日移动平均以消除单日噪声。
- 滚动 3 年百分位后**反转**：比值高 = 短期恐慌 = 恐惧 = 低分。
- 数据源：CBOE cdn（`VIX_History.csv` 自 1990、`VIX3M_History.csv` 自 2009），日频完整。

**已知代价**：F2 与 F1（VIX 水位）同属波动率族，存在共线性。记入 §17 风险，实现时须做因子相关性检查（要求 |corr| < 0.8），超标则改用备选因子（如 IWM/SPY 小盘相对强弱，数据已具备）。

#### F3 价格因子（先验权重 30%）

四个子项，各自归一后**等权**平均：

| 子项 | 定义 | 方向 |
|---|---|---|
| 动量 | QQQ 的 20 日与 60 日收益率 | 高分=贪婪（正向） |
| RSI | QQQ 的 RSI(14) | 正向 |
| 回撤 | 距 52 周（252 交易日）最高收盘价的回撤幅度 | 反转（回撤大=恐惧） |
| 波动率 | QQQ 的 20 日已实现波动率（年化） | 反转（波动大=恐惧） |

归一化：滚动 3 年百分位。

**输入口径约束（见 §4.5 约束 1）**：F3 的四个子项全部基于 **QQQ（标的指数代理）**，**禁止使用 TQQQ 等杠杆 ETF 自身价格**——杠杆 ETF 价格含年化 12%~38% 的波动率拖累，会把损耗系统性误读为恐惧。F4 同理，输入全部为无杠杆标的。

#### F4 广度代理（先验权重 20%）

三个子项，各自归一后**等权**平均：

| 子项 | 定义 | 方向 |
|---|---|---|
| 等权/市值权强弱 | RSP/SPY 比值的 60 日变化率 | 正向（广度改善=贪婪） |
| 成长/大盘强弱 | QQQ/SPY 比值的 60 日变化率 | 正向 |
| 均线宽度 | SPY、QQQ、RSP、IWM 中收盘价在 200 日均线上方的比例（0/0.25/0.5/0.75/1） | 正向 |

归一化：前两项用滚动 3 年百分位；均线宽度本身已是有界值，直接 `×100`。

### 5.3 归一化方式：滚动分位数，不用固定阈值

**必须用滚动 3 年百分位，而不是固定阈值。** 理由：VIX 在 2017 年"20 就算恐慌"、在 2020 年"50 才算"，固定阈值会让指数在不同年代失去可比性，回测结论会被"哪个年代"污染。滚动百分位让指数始终表达"相对当下环境的情绪位置"，这是跨 10 年回测成立的前提。

窗口长度 `rank_window = 756`（3 年），列入可调参数（见 §16）。

### 5.4 合成与缺失处理

```
fg_index = Σ (w_i × score_i) / Σ w_i      # 仅对当日有效的因子求和
```

- 任一因子当日为 NaN 时，从分子分母中同时剔除，**按剩余有效权重重新归一化**。
- 若有效因子数 < 2，当日 `fg_index = NaN`，不产生信号（避免单因子主导）。
- **禁止**用任何全样本统计量（如全期均值/标准差）做归一化，只能滚动窗口。

### 5.5 warmup 规则

`fg_index` 需要滚动 3 年窗口才有值，因此：

- 有效指数最早出现在数据起点后 **756 个交易日**（约 3 年）。
- 若数据起点为 2010 年，有效信号从 2013 年左右开始。
- 回测区间相应设定（见 §11.5）。

## 7. 信号层：资金结构

### 7.1 资金结构（独立弹药池）

资金分两部分，**上限合计 100%**：

| 部分 | 上限 | 驱动信号 |
|---|---|---|
| 核心仓 | 70% | 贪恐指数五档 |
| 弹药仓 | 30% | 回撤档位（三批，每批 10%） |

### 7.2 核心仓五档映射

五档比例先映射为 0-100 的"核心仓饱和度"，再乘以 70%：

| 指数区间 | 档位 | 饱和度 | 核心仓实际仓位 |
|---|---|---|---|
| 0-20 | 极度恐惧 | 100% | **70.0%** |
| 20-40 | 恐惧 | 75% | **52.5%** |
| 40-60 | 中性 | 50% | **35.0%** |
| 60-80 | 贪婪 | 25% | **17.5%** |
| 80-100 | 极度贪婪 | 0% | **0.0%** |

### 7.3 弹药仓释放规则

回撤基准：**标的指数（QQQ / SOXX / SPY）的滚动 52 周（252 交易日）最高收盘价**。

**口径约束（见 §4.5 约束 2）**：必须用**标的指数**而非杠杆 ETF 自身价格。理由：① 杠杆 ETF 自身回撤含年化 12%~38% 的波动率拖累，长期会"自然"触发，与市场情绪无关；② 3 倍杠杆下标的跌 7% 即表现为 -20%，三批弹药会被过快耗尽。用标的指数口径，-20% / -40% / -60% 才对应真实的熊市深度。

选用滚动窗口而非历史最高点，避免历史极值导致此后长期处于"满弹药"状态。

| 触发 | 释放 |
|---|---|
| 回撤 ≥ 20% | 第 1 批 10% |
| 回撤 ≥ 40% | 第 2 批 10% |
| 回撤 ≥ 60% | 第 3 批 10% |

- 每批**只释放一次**，释放状态持久化在 `Data/state.json`。
- **弹药仓释放后长期持有**，不因回撤修复而卖出。它只受 §8.1 极贪熔断的减仓规则管理。
- 回撤基准随滚动窗口移动，因此"重新触发"需要先修复再跌破——但因每批只释放一次，不存在重复释放问题。

### 7.4 目标仓位

```
target_position = core_position + ammo_position
```

其中 `core_position ∈ {0, 17.5, 35, 52.5, 70}`，`ammo_position ∈ {0, 10, 20, 30}`。

多标的分配（v1）：`target_position` 在三只标的上**等权分配**（各 1/3）。v2 再改为按各标的 F3 价格因子分加权。

## 8. 极端规则（优先于档位映射）

### 8.1 极贪熔断（条件解锁版）

**触发**：`fg_index ≥ 85`。

**动作**：
- 总仓位减至 **25% 底仓**（不清仓——避免完全踏空后续反弹）。
- 熔断后 **3 个交易日内禁止买入**（仅防熔断当日冲动追高，不做长期锁定）。
- 熔断状态持久化在 `state.json`。

**解锁条件（满足任一即恢复正常档位规则）**：
1. `fg_index < 60`；
2. **标的级独立解锁**：某标的自熔断后低点**反弹 ≥ 10%** → 仅该标的恢复常规档位规则，未满足的标的继续保持熔断状态；
3. `fg_index` 自熔断峰值回落 **≥ 15 点**。

熔断期的 25% 底仓按标的等权分配（各约 8.33%）。条件 1 与 3 为全局解锁，条件 2 为标的级解锁。

**设计说明**：初版曾设计"清仓 + 30 日禁买"，被否决。理由是对 3 倍杠杆标的而言，错过后继反弹的代价过大，且"禁买期"是时间锁，无法感知市场实际反弹。改为条件解锁后，"关注后续反弹"从主观判断变为三条可量化、可回测的线。

### 8.2 极恐加仓

**触发**：`fg_index ≤ 10`。

**动作**：
- 核心仓强制打满 70%（五档下"极度恐惧"已给 70%，故此项主要影响 §7.2 边界抖动情况）。
- **允许提前释放下一批弹药**（即使回撤未达 20%/40%/60%），每次极恐事件最多提前释放 1 批。
- 两次极恐事件间隔需 ≥ 60 **交易日**才可再次提前释放（`extreme_fear_cooldown_days`）。

  > 实现口径说明：`signal` 层只接收日期字符串、没有交易日历，因此参数以**自然日**表达，取 **84 天**（≈60 交易日 × 7/5）。若要精确按交易日计数，需把交易日索引传入信号层——v1 未做，属已知近似。

**设计说明**：这是"极恐加倍买入"的落地方式——在资金结构下，核心仓已有 70% 上限，"加倍"只能体现在弹药池的提前释放上，否则该规则没有实际作用空间。

### 8.3 规则优先级

```
极贪熔断（§8.1） > 极恐加仓（§8.2） > 五档映射（§7.2）
```

极端规则触发时，**豁免** §9 的防抖动约束。

|---|---|---|

## 10. 前视偏差红线

这是整条链路的**红线**，违反则回测结果全部无效。

1. 所有因子只使用 ≤ T 日的数据。
2. **VIX / Put-Call 的实际发布时点晚于当日收盘** → 统一 `shift(1)` 后参与合成，即 T 日信号实际消费 T-1 的情绪数据。
3. `target_position` 序列喂给 backtrader 前**整体再 `shift(1)`**，确保 T 日开盘执行的是 T-1 收盘算出的信号。
4. 滚动窗口统计量（百分位、最高价、波动率）必须使用 `min_periods` 严格限制，不足窗口期返回 NaN，禁止用不足窗口的数据凑出值。
5. **状态化规则**（弹药释放、冷却计数、熔断解锁）在回测中必须**按时间顺序逐日增量推进**，禁止用全样本信息（例如"全期最高价"、"全期回撤"）一次性计算。
6. **校验测试（必须实现）**：把 `features.csv` 中所有输入列整体向后平移一天重跑管道，`fg_index` 序列必须逐日完全相同。若不同，说明有未来数据渗入。

## 11. 回测设计

### 11.1 数据接入

```python
class FgPandasData(bt.feeds.PandasData):
    lines = ('fg_index', 'zone', 'target_position')
    params = (('fg_index', -1), ('zone', -1), ('target_position', -1))
```

`features.csv` 直接喂入，日期为索引，升序。

### 11.2 策略体

`FgStrategy.next()` 只做一件事：

1. 读取 `self.datas[0].target_position[0]`（已 shift，无前视）。
2. 与当前仓位比较，套用 §9 阈值/冷却/单次上限。
3. 用 `order_target_percent` 下单。

backtrader 市价单默认**次日开盘价成交**，天然满足"T 日收盘信号、T+1 执行"。策略内**不允许出现任何指标计算或条件判断**——所有决策已在 `signal` 层完成。这条约束保证"回测逻辑 = 日常运行逻辑"。

## 13. 交易纪律闭环

### 13.1 每日指令卡

系统每次运行 `pipeline` 输出一张文本指令卡：

```
日期：2026-09-21
fg_index：23.4（恐惧）
核心仓：52.5%   弹药仓：10%   目标总仓位：62.5%
当前仓位：50.0%
指令：可操作 → 加仓 12.5pp（未超单次上限 30pp）
下次可调仓日：2026-09-28
熔断状态：正常
```

### 13.2 交易记录与违规审计

- `Data/trade_log.csv` 记录每一笔真实操作：`date, symbol, action, quantity, price, reason`。
- `audit.py` 对比实际记录与系统指令，输出标记：

| 标记 | 判定条件 |
|---|---|
| 合规 | 操作方向与幅度在指令范围内 |
| 超频违规 | 距上次操作 < 冷却期（5 交易日） |
| 逆向违规 | 操作方向与指令相反 |
| 超幅违规 | 单次调整幅度 > 30pp |
| 无指令操作 | 当日系统标记"不可操作"仍执行了交易 |

- 输出**违规率**（违规笔数 / 总笔数）作为纪律执行的量化指标。

### 13.3 核心原则

**指令之外的操作一律记为违规。** 违规记录本身就是约束力的来源——系统的价值不在于给出完美信号，而在于让"偏离规则"这件事被记录、被看见。

## 14. 测试策略

### 14.1 因子层单测

- 每个因子的 `score` 输出范围恒在 [0, 100]。
- **反转方向正确**：构造"VIX 从 10 涨到 50"的序列，F1 分数必须**下降**；构造"Put/Call 从 0.5 涨到 1.5"，F2 分数必须**下降**。
- 滚动窗口不足时返回 NaN，且 NaN 数量符合预期。
- `stale_days > 5` 时 F2 返回 NaN。

### 14.2 前视偏差校验

- §10.6 的平移测试（必须通过）。
- 检查 `features.csv` 中不存在任何"当日后才可知"的列。

### 14.3 规则单测

- 弹药池：回撤依次穿越 20%/40%/60% → 释放 10%/20%/30%，且各批只释放一次。
- 冷却：连续两日目标仓位跳变 → 只有第一天产生调仓指令。
- 单次上限：目标仓位跳变 50pp → 实际调整 30pp。
- 熔断：指数从 90 跌到 59 → 解锁；指数维持 88 → 保持熔断状态。
- 熔断反弹解锁：熔断后标的从低点反弹 10% → 解锁。
- 极恐提前释放：指数 ≤ 10 且 60 交易日内已释放过 → 不重复释放。

### 14.4 指数合理性定性校验

将 `fg_index` 与已知市场事件对照（2020-03 疫情暴跌、2021-11 顶部、2022-10 底部、2024-08 波动率冲击），检查指数在这些时点的取值方向是否合理。**只做定性对照，不追求与任何外部指数数值一致。**

### 14.5 稳健性测试

- 分区间独立评估：2014-2018 / 2019-2021 / 2022-2024 / 2025-至今。
- 参数敏感性：档位阈值 ±5、滚动窗口 2/3/5 年、调仓阈值 5/10/15pp。若结论对参数极度敏感，说明是曲线拟合而非真实规律。

### 14.6 拆股 / 合股校验测试（强制）

对应 §4.4，这是防止"假跳空污染整条决策链"的防线：

1. **拆股日连续性测试**：遍历 `splits.csv` 中 `verified=1` 的每个事件，断言复权后拆股日前后单日涨跌幅 < `split_continuity_tolerance`（默认 5%）。若失败，说明复权失效。
2. **异常跳变检测测试**：构造一段含 2:1 拆股但**未复权**的价格序列（拆股日人为 -50%），断言 pipeline 抛出异常并中止。这是对 fail-fast 机制本身的测试。
3. **正常极值不误报测试**：用两个真实极值断言**不触发**中止——① SOXL 2025-04-09（+54.79%，与 3×SOXX 偏离 0.92pp）；② SOXL 2020-03-17（与 3×SOXX 偏离 **16.46pp**，全区间最大真实偏离，用于锁定 20pp 阈值的下界）。
4. **日期规范化测试**：构造 `MM/DD/YYYY` + 降序的输入，断言输出为 `YYYY-MM-DD` + 升序，且内容一一对应无错位（注意 `01/02/2020` 这类歧义日期必须按 `MM/DD` 而非 `DD/MM` 解析）。
5. **复权口径一致性测试**：同一标的前复权序列与后复权序列的**日收益率序列**必须完全相等（容差 1e-9）。若不等，说明复权实现有误。

## 15. 外部贪恐指数（决定：不接入，人工参考）

### 15.1 探测结论（2026-09-21）

对 `https://fe.szdt.tech/invest/#/`（守猪逮兔，用户付费会员，299 元/年）做了完整可行性探测：

| 项 | 结果 |
|---|---|
| 站点可达性 | **可达**，但必须经 PAC 指定的公司代理 `10.30.6.49:9090`。`10.1.82.22:3128` 是 **pip 专用代理**，对通用外网目标返回 403——这是最初误判"站点不可达"的原因。**分工结论：pip/依赖下载走 `10.1.82.22:3128`，通用外网访问走 `10.30.6.49:9090`** |
| 站点形态 | 阿里云 OSS 静态前端（SPA）+ 独立后端 API |
| 后端 API | `https://szdt.tech/api`，请求需 HMAC-SHA256 签名 + 用户 token 双鉴权 |
| 数据接口 | `GET /invest/emotion` 返回 9 个当日温度指标：美股温度、A股温度、港股温度、韩股温度、黄金温度、数字货币温度、逆回购 1 天期利率、美元存款利率、USD/CNY 汇率 |
| **历史数据** | **不存在**。查询参数（`date`/`type`/`limit`）被服务端忽略，`/emotion/history` 等路径均 404 |
| 未授权访问 | 返回 `score = 0`（脱敏）。实测确认：**无 token 时数值被隐藏**，需用户 token 才能获得真实值 |

**关键限制：该接口只提供当日快照，不存在历史序列，因此不可能用于历史回测。**

### 15.2 决策：不接入

**v1 不做任何程序化接入。** 理由：

1. **无法回测**——只能从接入日起逐日累积，价值边际且见效极慢。
2. **合规成本大于收益**——该服务为付费产品，签名密钥硬编码在前端，说明官方并未开放 API。用自己账号数据做个人参考风险可控，但没有必要为边际价值承担这个风险。
3. **自建指数才是决策源**——外部指数在本设计中本就只是"参考"，不参与任何仓位计算。

> **勘误记录（2026-09-23）**：本节理由 2 的后半句
> 「**签名密钥硬编码在前端，说明官方并未开放 API**」**已被证伪**。
>
> 用户于 2026-09-23 提供了官方开发文档 `docs/查询实时贪恐.docx`，其中定义了
> **官方 partner API**：
>
> ```
> POST https://szdt.tech/api/partner/invest/stock/scan
> Header:    X-Auth: <会员激活码>
> form-data: code / lever / emo_area
> ```
>
> 该文档含完整参数说明、响应结构与**额度规则**（`query` 30 个标的 / 30 天，
> `query_api` 5000 次 / 自然月），文档属性 Creator / Updater 为 `V` ——
> 这是**官方开放给会员的接口**，不是"前端硬编码的密钥"。
>
> 当时判定「未开放 API」的真实原因是**拿错了契约**：实测用的是
> `GET /api/invest/stock_emotion?etf_type=1`，而正确方法是 `POST`、
> 正确路径是 `/api/partner/invest/stock/scan`、且缺 `X-Auth` 与三个 body 参数
> —— **四处同时出错**。服务端返回的
> `{"status":2,"msg":"参数校验失败，IP 已记录"}` 被读成了「需要未知的鉴权参数」。
>
> **⚠️ 本节其余结论仍然成立**：理由 1「无法回测」（该接口确实只给当日快照）、
> 理由 3「自建指数才是决策源」均不受影响。另需注意 §15.1 表格中
> `GET /invest/emotion`（9 个温度指标）是**另一个端点**，本次勘误
> **不涉及**它是否也在 partner 开放范围内 —— **未探测，不得推断**。
>
> 完整契约、额度核算与影响分析见 `docs/trading-discipline.md` 第 14.5 条。

### 15.3 人工参考机制（保留）

1. 仪表盘第 6 区块保留**对照参考线**，数据来源为人工录入。
2. 两种录入方式：直接编辑 `Data/raw/external_index.csv`（字段 `date,value,note`），或 CLI 单条录入。
3. 数据缺失时该区块留空，**不影响任何其他功能**。
4. **外部指数永远不参与仓位计算**，仅用于事后复盘对照（例如复盘时回看："我按系统减仓那天，外部指数在什么位置"）。
5. 即使两者背离超过 30 点，也**不触发任何告警或动作**，仅作为复盘时的观察点。

### 15.4 探测脚本处置

设计阶段的探测脚本（含第三方签名细节）**已删除，不纳入交付物**。本节保留结论性记录，供后续如需重新评估时参考。若将来要重新评估，需重新探测。

## 17. 风险与已知局限

1. **样本外区间偏短**：2023-至今约 3.5 年，结论的统计置信度有限。
2. **杠杆 ETF 损耗与"回撤优先"目标存在内在冲突（本设计最大的张力）**：损耗 ∝ σ²，且随持有期线性累积（§4.5：TQQQ 持有 3 年中位损耗 -58.93%，SOXL 年化损耗 46.81%）。"恐惧时满仓"意味着在**波动率最高**的时期持有**损耗最贵**的产品。降低仓位能减少损耗，但也会减少上涨时的收益——这个权衡无法消除，只能量化并接受。v1 通过损耗归因表（§11.6）让这个代价可见。
3. **因子共线性**：F1（VIX 水位）与 F2（VIX/VIX3M 期限结构）同属波动率族，F3 的波动率子项也相关，等权合成可能多重计价波动率。实现时须做相关性检查（|corr| < 0.8），超标则把 F2 替换为 IWM/SPY 小盘相对强弱（数据已具备）。
4. **滚动分位数的历史依赖**：极端行情会"挤出"窗口内的历史样本，导致极端值本身难以被百分位识别（例如连续 3 年高波动时，VIX 40 可能只算中位）。§8 的绝对阈值规则（85/10）正是为了兜住这个盲区。
5. **外部指数无法回测**：见 §15——该数据源只有当日快照，无历史序列，因此设计上完全不依赖它。
6. **过拟合风险**：缓解措施为——固定先验权重不做全样本优化、严格样本内/外划分、稳健性测试（§14.5）、参数敏感性测试。
7. **回撤目标可能达不到**：-35% 是目标而非承诺。若样本外回撤显著超出，应优先调整资金结构（降低核心仓上限）而非反复调参。
8. **数据源集中风险**：v1 的价格数据全部依赖 **Nasdaq 官方 API** 单一源。若该接口变更或失效，需切换备选源，切换后**必须重新核对复权口径与拆股记录**并重跑 §14.6 全部测试，否则历史回测结论会因拆股假跳空而整体失效。
9. **合股（reverse split）风险**：杠杆 ETF 在长期熊市中可能合股以维持价格，其跳空方向与拆股相反（价格暴涨）。§4.4 的检测与 §14.6 的测试对两个方向同时生效，但 `splits.csv` 必须同时记录合股事件（`ratio < 1`）。
10. **Nasdaq 数据的分红复权未验证**：已确认其 `Close/Last` 含拆股调整，但**未验证是否含分红调整**。对杠杆 ETF 影响极小（分红极少），对 SPY/RSP 约低估 1%/年。实现时须与另一源抽样比对确认。
11. **Put/Call 数据源停更**：CBOE 官方 Put/Call CSV 止于 2019-10，F2 已改为波动率期限结构（§5.2）。若将来找到完整 Put/Call 源，可恢复该因子并做 A/B 对比。
12. **损耗参数为实测标定，未来会漂移**：§4.5 的产品损耗率（TQQQ 8.22% 等）基于 2016-2026 的利率环境标定，**加息或降息周期下会显著变化**。回测中使用固定值会低估或高估未来损耗，参数须定期重标定。
13. **warmup 长达 3 年，系统上线后前 3 年无信号**（实测：数据起点 2016-09-19 → 首个有效信号 2019-09-27）。根因是滚动分位窗口 `RANK_WINDOW=756` 交易日。这是"用滚动分位保证跨周期可比性"这一决策的必然代价——若缩短窗口（如 252 日）可让系统更快可用，但会让指数在不同年代失去可比性（§5.3）。**必须在启用前明确：系统不是"上线即生效"，而是"上线后需积累 3 年数据"**；若要缩短，属于设计级变更。
14. **回撤目标未达成（实测 -61% ~ -73%，目标 ≤35%）**：根因是"恐惧时满仓"在**持续熊市**中会演变为接飞刀（2022 年 TQQQ 跌 79.7%，策略持仓均值 73.1%）。这是策略逻辑的固有特征而非实现缺陷。改进方向见 `docs/superpowers/plans/2026-09-21-acceptance-report.md` §5（推荐增加趋势过滤），但**任何改动都必须走 `docs/trading-discipline.md` 第 8 条流程，禁止直接调参**。
