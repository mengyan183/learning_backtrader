## 二、趋势过滤：v2 核心改动的价值（设计文档 §8.4 强制输出）

```
基准 QQQ，全区间 2016-09 ~ 2026-09
  with_trend_return     +142.97%
  without_trend_return  +132.35%
  return_delta           +10.62%      ← 趋势过滤带来的收益改善
  with_trend_mdd         -22.64%
  without_trend_mdd      -29.75%
  mdd_delta               +7.11pp     ← 趋势过滤降低的回撤
  blocked_days           413（占 16.4%）
判定：effective = True
```

分区间：

| 区间 | 收益改善 | 回撤改善 | 触发天数 |
|---|---|---|---|
| 样本内 2019-09 ~ 2022-12 | +8.44% | +7.11pp | 256 |
| 样本外 2023-01 ~ 至今 | **-5.58%** | +3.96pp | 76 |
| 2022 熊市 | **+7.98%** | **+7.31pp** | 235 |

**解读**：趋势过滤在**熊市中贡献显著**（2022 年 +8% 收益、回撤改善 7.3pp），在**牛市中付出代价**（样本外 -5.58%）。这正是「回撤优先」目标下的预期权衡。

**结论：趋势过滤值得保留**（设计文档 §12 风险 7 的「若贡献度接近零则回退到选项 A」未触发）。

## 三、大盘回撤：目标未达成，但方向正确

```
=== v2 大盘回测（含趋势过滤，目标 = us_core + 弹药仓）===
标的     策略年化    策略回撤 | 买入持有年化  买入持有回撤
TQQQ     18.66%    -50.21% |    39.87%     -81.75%
SOXL     25.03%    -59.43% |    45.91%     -90.51%
UPRO     12.24%    -56.20% |    28.80%     -76.82%

对比 v1（无趋势过滤）：-61.53% / -73.33% / -60.56%
```

**根因分析**：

趋势过滤把回撤从 -61.53% 压到 -50.21%（TQQQ），改善 11.32pp，但离 -40% 仍差 10pp。原因：

1. **趋势过滤只压上限，不改变「恐惧时买入」的核心逻辑**。在 2022 式持续熊市中，指数长期处于恐惧区，五档给出高饱和度，趋势过滤只能把它减半——**半仓仍要吃下大部分跌幅**。
2. **大盘核心仓上限 49% + 弹药 30% = 79% 上限**，在 2-3 倍杠杆下仍属高暴露。
3. 本报告的回测口径把**整份共享弹药池**计入大盘（近似），若按实际分摊，大盘暴露会更低——但也意味着加密部分承担更多。

**下一步建议（按设计文档 §12 风险 7 的预设处置）**：

**回到 v1 验收报告的选项 A —— 降低核心仓上限**（`CORE_CAP` 70% → 40~50%）。这是**设计级变更**，必须走 `docs/trading-discipline.md` 第 8 条流程（先改文档 → 再改代码 → 再回测）。**不要继续调趋势过滤的参数**（`TREND_MA_DAYS` / `TREND_FILTER_FACTOR`）——那是过拟合的典型入口。

### 4.2 关键发现：2 倍加密 ETF 的最大回撤是灾难级的

真实轨最大回撤 **-85% ~ -99.6%**，比 TQQQ 的 -81.75% 更惨烈，**MSTX/MSTU 接近净值归零**。

这直接验证了设计文档 §12 风险 11：「加密层仓位上限本身就是风险控制，不允许因为『跌得多了很便宜』而突破上限」。

**对实操的含义**：加密三层上限（100% / 70% / 50%）不是保守，是**必要**。若按等权配置，MSTX 的 -99.6% 会吞噬整个组合。

### 4.3 加密信号有效起点：2021-02（**比设计预期短**）

设计文档 §4.2 设想合成轨覆盖 2018 熊市。**实际做不到**：CF1 的输入（alternative.me 贪恐指数）**2018-02 才开始**，叠加 756 日滚动窗口 → 首个有效值到 **2021-02-02**。

- 实际覆盖：2021-02 ~ 2026-09（5.6 年）
- **包含 2022 熊市** ✓
- **不含 2018 熊市** ❌（设计预期未达成）

这是「用滚动分位保证跨周期可比性」（v1 §5.3）的必然代价，与 v1 的 warmup 问题同源。

### 4.4 共享弹药池（设计文档 §6.4）

- 全区间共释放 **3 批**（池子上限）
- 冲突处理按「回撤 / 当前待释放批次阈值」比值排序，平局大盘优先
- 分配日志见 `Data/portfolio_features.csv` 的 `ammo_released` 变化时点

### 4.5 跨市场相关性（设计文档 §12 风险 8）

```
全区间相关性: -0.020
危机期相关性: -0.118
判定: 危机期相关性 -0.12，在可接受范围
```

**统一资金池未产生隐性集中风险**（告警阈值 0.7 未触发）。这消除了设计阶段对「一个市场崩盘拖累另一个」的担忧。

## 五、实施中发现并修复的真实缺陷（4 处）

这 4 处**都不是测试问题，是实现或设计的真实缺陷**，若不修会导致规则静默失效：

| # | 缺陷 | 后果 | 修复 |
|---|---|---|---|
| 1 | **v1 `parse_nasdaq_rows` 只剥离 `close` 的 `$`** | Nasdaq 对 `assetclass=stocks` 的所有价格字段带 `$`（`'$168.50'`），v1 只在 `close` 上剥离 → **MSTR/COIN 的 2513 行全部被静默 skip**，返回空表 | 新增 `_num()` 统一剥离 |
| 2 | **合成模型系统性乐观偏差** | 实测反推所需年化成本率：BITX 30.2% / MSTX 57.9% / CONL 2.2%。这些**不是费用**，是模型未捕捉的机制（BTC 期货展期升水、单股互换融资价差） | 改为**实测校准 + 强制披露**，不用假成本率掩盖 |
| 3 | **加密极贪档位是死代码** | 原实现 `core = core × greed_tier_factor(tier)`，但五档在指数 ≥80 时已给饱和度 0 → **档位永远对着 0 做乘法**，违背 §6.5「不一次性清仓、分批递减」的初衷 | 改为**档位替换五档饱和度**（设下限） |
| 4 | **大盘熔断底仓是死代码** | 原实现 `core = min(core, full × 0.25)` 是**取上限**，而熔断在 ≥85 触发时五档已给 0 → `min(0, …) = 0`，**v1 的「25% 底仓（不清仓）」在 v2 从未生效** | 改为 `core = full × cb_floor`（替换） |

**缺陷 3 与 4 是同一个模式**：五档在 ≥80 就清仓，而所有「极端规则」都在 ≥85 才触发，于是全部变成对着 0 做乘法。两处都加了「断言 > 0」的回归测试。

**缺陷 2 的完整校准表**（写入 `config.CRYPTO_PRODUCT_COST_RATE`）：

| 标的 | 校准前 | 校准后 | 校准后残留偏离 | 是否超合理费率(15%) |
|---|---|---|---|---|
| BITX | 1.05% | **30.17%** | +0.2494% | 是（BTC 期货展期升水） |
| BITU | 1.05% | **22.85%** | +0.2394% | 是 |
| MSTX | 1.20% | **57.90%** | +0.1120% | 是（单股互换融资价差） |
| MSTU | 1.20% | **35.29%** | +0.1807% | 是 |
| CONL | 1.05% | **2.16%** | +0.0582% | 否（合理费用） |

CONL 只需 2.16% 就匹配，**证明模型原理正确**；其余标的的超高值说明其拖累来自模型未捕捉的机制。

### 5.1 前视偏差红线：BTC 数据的 1 日相位错位

`blockchain.info` 返回的是 **7×24 日均价**（API 原文 "Average USD market price"），统计窗口跨越美股会话，与 ETF 单日收益存在约 1 个交易日相位差：

```
corr(BITX, BTC)  lag=0 → 0.173
corr(BITX, BTC)  lag=+1 → 0.773    ← 相关性强得多
```

**实施中一度倾向用 `shift(-1)` 对齐——被否决**：那等于用「明天」的 BTC 配「今天」的 ETF，是前视偏差。

**最终处置**：**不做任何 shift**，改用 **5 日累计窗口**做异常检测以稀释伪影（`CRYPTO_ANOMALY_WINDOW = 5`）。同时修复了「缺 BTC 时 BITX/BITU 静默跳过、从未被检测却输出『通过』」的漏洞。

**已知代价**：噪声 39.14pp ↔ 拆股信号 50pp，余量仅 11pp（v1 是 16pp ↔ 50pp）。已在 `config.py` 注释说明：若将来拆股信号被漏检，**应加宽窗口而非上调阈值**。

## 七、已知遗留问题

1. **大盘 -40% 目标未达成**（实测 -50.21% ~ -59.43%）。根因是核心仓上限仍过高，趋势过滤只能减半不能归零。**下一步应走选项 A（降低 `CORE_CAP`）**，属设计级变更。
2. **加密回撤目标未达成**（实测 -85% ~ -99.6%，目标 ≤-50%）。这是 2 倍加密 ETF 的产品特性（MSTX 接近归零），**不是策略缺陷**——但也说明加密层的上限设置必须极其保守。
3. **加密信号起点为 2021-02**，未覆盖 2018 熊市（设计预期未达成）。根因是 CF1 输入 2018-02 才开始 + 756 日 warmup。
4. **合成轨的绝对收益按构造校准，不具预测性**，且校准基于 2022-2026 的利率与升水环境，外推到更早期间存在不确定性。任何收益结论应优先引用真实轨。
5. **加密异常检测的判别余量较窄**（噪声 39pp ↔ 拆股 50pp）。
6. **`CRYPTO_EXTREME_FEAR_TRIGGER` 与 `CRYPTO_SPLIT_*` 为实测标定值**，市场结构变化时需重新标定。
7. **回测口径的近似**：`backtest-v2` 把整份共享弹药池计入大盘，未按市场分摊。组合级真实暴露见 `Data/portfolio_features.csv`。
8. **v1 遗留的换手率问题未验证**：v1 实测 37 次/年偏高。v2 引入趋势过滤后目标仓位更稳定，换手率有望下降，但本报告未单独度量。
