## 二、补齐的设计缺口

v2 设计 §6.3 只给了三层**上限**（80/50/30%），**没定义层间实际配置**。补齐：

```
层权重 = 该层上限 / Σ各层上限      （80/50/30 ⇒ 50% / 31.25% / 18.75%）
层内权重 = 层权重 / 该层标的数
```

| 标的 | 层 | 权重 |
|---|---|---|
| BITX / BITU | BTC 纯 Beta | 各 25.00% |
| MSTX / MSTU | 币股高 Beta | 各 15.625% |
| CONL | 币股经营 Beta | 18.75% |

让「风险越靠间接的一端、配置越少」（§6.3 意图）**真正生效**，
而不是只当一个可能永不触发的上限。**禁止**另发明层间权重（会引入第二个自由度）。

---

## 三、⚠️ 重大口径修正：共享弹药池被加密全部拿走

| 市场 | 实际释放批次 | 弹药 |
|---|---|---|
| **加密** | **3 / 3（全部）** | **20.00%** |
| 大盘 | **0 / 3** | **0.00%** |

**根因**：共享池按「回撤 / 当前待释放批次阈值」比值裁决。加密档位虽按比例加宽
（-30/-50/-70），但**加密崩得更深**，比值反而更大——
**加宽档位没有达到「防止加密抽干池子」的设计目的**（§6.4 原话）。

**后果**：`backtest-v2` 把整份共享池记在大盘头上（v2.3 起标注为「近似」），
**严重高估大盘暴露**（记 51.5%，实际只有 **31.5%**）。本次改为**分市场记账**
（`ammo_us` / `ammo_crypto`）。

## 四、修正后的真实画面

| sleeve | 最大暴露 | 最大回撤 | 年化 | 波动率 |
|---|---|---|---|---|
| **大盘**（核心仓 + 大盘弹药 = 核心仓） | **31.5%** | **-19.52%** | 6.57% | 9.27% |
| **加密**（核心仓 + 全部弹药） | **33.5%** | **-55.52%**（合成轨） | **-1.74%** | 28.91% |

### 4.1 风险完全错配

1. **大盘只跌 -19.52%**，**远优于 -40% 目标**——v2.4 按「51.5% 暴露」做的
   `CORE_CAP` / `AMMO_CAP` 定值**建立在高估的暴露上**，偏保守。
2. **加密是主要风险源**：最大暴露 33.5%、回撤 -55.52%，对总资金回撤贡献约 **-18.6pp**。
3. **加密年化为负**（合成轨 -1.74%、真实轨 -1.05%），跨市场相关性仅 **-0.020**
   （危机期 -0.118）——**分散化收益也很弱**。

### 4.2 加密复核矩阵（合成轨）

每格「`sleeve 最大回撤` / `对总资金回撤贡献` / `sleeve 年化`」：

| 加密占核心仓 | 80/50/30（当前） | 100/70/50（v2 原值） | 70/35/15（更偏 BTC） |
|---|---|---|---|
| 15%（核心 6.8%） | -43.62% / -11.7pp / -2.01% | -42.12% / -11.3pp / -2.27% | -43.77% / -11.7pp / -1.72% |
| 20%（核心 9.0%） | -44.66% / -13.0pp / -2.09% | -43.10% / -12.5pp / -2.35% | -44.93% / -13.0pp / -1.79% |
| **30%（核心 13.5%，当前）** | **-55.52% / -18.6pp / -1.74%** | -44.65% / -15.0pp / -0.19% | -55.57% / -18.6pp / -1.45% |
| 40%（核心 18.0%） | -48.60% / -18.5pp / -0.26% | -49.53% / -18.8pp / -0.74% | -47.00% / -17.9pp / +0.27% |

**矩阵不足以支撑「最优」结论**：格子**非单调**（30% 处 -55.52% 与 100/70/50 的
-44.65% 差 10.9pp），结果被 **MDD 窗口切换**主导。**但方向清楚**：
降低加密分配能同时降低回撤贡献，且加密本身年化为负。

## 六、实施中发现并修复的真实缺陷（3 处）

| # | 缺陷 | 后果 | 修复 |
|---|---|---|---|
| 1 | **共享弹药池记账错** | 整份池子记在大盘头上，暴露高估 20pp（51.5% vs 31.5%） | 新增 `ammo_us` / `ammo_crypto` 分市场记账 |
