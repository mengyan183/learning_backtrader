# 毛选方法论：四条决策框架

用四条经实践检验的方法论做决策与复盘。每条给：原理 → 本系统怎么用 → 检查问题。

## 1. 调查先行——《反对本本主义》

> "没有调查，就没有发言权。"

**原理**：任何结论先有事实；不调查就下判断 = 本本主义。
**本系统怎么用**：所有数字指回本地文件（features.csv / positions.csv / shoutu_fng.csv），查不到就直说；禁止编数字、编日期、编系数。LLM 永不判决，回测 + pytest 是唯一裁判。
**检查问题**：
- 结论里的每个数字能指回哪个文件、哪个日期？
- 有没有"凭感觉/凭常识"代替数据的地方？

## 2. 矛盾分析——《矛盾论》

> "任何过程如果有多数矛盾存在的话，其中必定有一种是主要的……捉住了这个主要矛盾，一切问题就迎刃而解。"

**原理**：多因子并存时必有主矛盾；抓主要矛盾，其余从属。
**本系统怎么用**：
- 简报归因：五因子（VIX/TERM/PRICE/BREADTH/FED）按「权重×偏离中性50」算合成贡献，贡献最大=主要矛盾，次大=对冲力量（`scripts/invest_research.py::_major_contradiction`）。
- 进化：一个阶段只攻一个主要矛盾，不并发摊薄。
**检查问题**：
- 当前驱动市场/盈亏的**一个**主因子是什么？它往哪个方向推？
- 次要力量在帮它还是对冲它？
- 手头任务里哪个是主要矛盾？其余是否可以先放下？

## 3. 分阶段——《论持久战》

> "敌进我退，敌驻我扰，敌疲我打，敌退我追。" / 战略防御—战略相持—战略反攻。

**原理**：大目标拆阶段，每阶段有明确状态与验收；不毕其功于一役。
**本系统怎么用**：
- 系统三层：回测验证（防御）→ 自动提案（相持）→ 信号扩展（反攻），一层不达标不进下一层。
- roadmap 分层：不依赖回测的先做，回测闭环恢复后做第二阶段。
- 新功能先声明处于哪一阶段，给阶段验收标准。
**检查问题**：
- 现在处在哪一阶段？验收标准是什么？
- 是否在"该推进时收缩、该收缩时冒进"？

## 4. 聚焦——《集中优势兵力，各个歼灭》

> "集中优势兵力，各个歼灭敌人"——每战集中绝对优势兵力，不打无把握之仗。

**原理**：资源有限时，撒网=分散火力；聚焦少数高确信目标逐个击破。
**本系统怎么用**：
- 仓位纪律：持仓数有限、单标的风险占比有预算；过度分散 = 同时押注所有方向。
- 开发纪律：一次一个主要矛盾（见第 2 条），不并行摊薄。
- 检查过度分散：持仓是否超过目标标的数？单标的是否超出风险占比上限？
**检查问题**：
- 持仓是否过度分散（数不过来、说不清每只为什么在）？
- 有没有一个标的风险占比过大且无纪律约束？

## 使用顺序（复盘/归因时）

1. **调查先行**：先取数据，禁止先给结论。
2. **矛盾分析**：找出主矛盾（最大贡献因子/核心驱动）。
3. **分阶段**：当前处于哪一阶段，下一步验收什么。
4. **聚焦**：下一步只做一件事，兵力集中。

## 例外与边界

- 方法论是决策辅助，不是数据替代：所有结论仍以系统数据与 pytest 为准。
- 不用于包装个人主观判断：先有数据，再有矛盾，再有阶段与聚焦。
- 不要为了"符合方法论"而强行套用；数据不足时如实说数据不足。
